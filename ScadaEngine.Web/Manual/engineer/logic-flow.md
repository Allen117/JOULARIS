# 流程圖控制與演算法

流程圖控制以拖拉節點、連線的方式建立自動控制邏輯：讀取點位 → 比較、邏輯閘、計時器、計數器、排程、演算法 → 寫入點位。Engine 持續執行所有啟用中的邏輯，適合做連鎖控制、排程啟停、台數控制、PID / 模糊控制等。

## 基本觀念

- **邏輯清單**：左側樹狀清單，可建資料夾分類；每一條「邏輯」是一張流程圖
- **啟用 / 停用**：只有啟用中的邏輯會被 Engine 執行；**停用的資料夾底下全部不執行**
- **Engine 執行頻率**：每 200 毫秒評估一次所有啟用邏輯；設定變更約 15 秒內生效
- **啟動保護期**：Engine 啟動後前 60 秒只評估、不寫入，避免重啟瞬間誤動作
- **Bad 傳遞**：上游點位品質 Bad 或演算法錯誤時，下游節點不評估、寫入節點本輪不寫

> ⚠️ 注意：流程圖會**真的寫入現場設備**。新邏輯預設停用；請先確認所有點位綁定正確，再啟用。

## 進入頁面

選單：**工程師模式 → 流程圖控制**

- **左側「邏輯清單」**：滑鼠移到項目上出現按鈕列：**新增資料夾**、**新增邏輯**、**啟用** / **停用**、**重新命名**、**刪除**
- **右側畫布**：選取邏輯後編輯流程圖，右上 **儲存**

## 節點一覽

| 節點 | 說明 |
|------|------|
| **讀取點位** | 讀取點位值；可勾 **讀取歷史值** 改讀 N 分鐘前的值（1～43200 分鐘，最長 30 天） |
| **寫入點位** | 把上游的值寫到點位（Modbus、DB 來源、OPC UA 可控點位） |
| **比較** | 小於 / 大於 / 小於等於 / 大於等於 / 等於 / 不等於，輸出 0 或 1 |
| **數學運算** | 加、減、乘、除、取餘數、次方、絕對值、平方根、四捨五入 |
| **常數** | 固定數值 |
| **AND 閘** / **OR 閘** / **NOT 閘** / **XOR 閘** | 邏輯閘 |
| **計時器** | **脈衝**、**延時開啟**、**重複脈衝**，設定延遲與持續秒數 |
| **計數器** | CTU：計數脈衝 (cu) 上升緣 +1，達目標值 (preset) 時達標輸出 (q) = 1；重置 (reset) 歸零。計數值不保存，Engine 重啟歸零 |
| **A接點** / **B接點** | 綁點位或排程，常開 / 常閉接點 |
| **排程** | 依「排程設定」判斷目前是否在排程時段內 |
| **演算法** | 呼叫演算法檔（Python / C#），見下方「演算法節點」 |

## 建立一條邏輯

1. 在邏輯清單按 **新增資料夾** / **新增邏輯**（新邏輯預設 **已停用**）
2. 選取該邏輯，在畫布空白處右鍵 → **新增節點**，選節點類型
3. 讀取 / 寫入 / 接點節點：點兩下或右鍵綁定點位，選擇器可切換 **設備點位**、**計算點位**、**DB 點位**、**需量點位**（唯讀）或 **排程**
4. 從節點右側輸出埠拖線到下游節點的輸入埠
5. 按 **儲存**（出現「儲存成功！」）
6. 確認無誤後，在邏輯清單對該邏輯按 **啟用**

畫布上的輔助：

- 多選節點後可用工具列對齊與等距分布
- 節點右鍵可 **變更類型**、**清除綁定**、**刪除節點**
- 未綁點位的讀取 / 寫入 / 接點節點會顯示灰色 **未綁定** 徽章
- 邊線顏色：綠色 = 正常有值；灰色 = 正常但訊號為 0；橘色 = 演算法警告；紅色 = 演算法錯誤（滑鼠移到邊線上可看原因）

> 💡 提示：寫入節點的值超出點位 Min～Max 時，邊線會標示 **超限**。

## 演算法節點

演算法節點呼叫放在 Engine 演算法資料夾內的程式檔，用來做 COP 計算、PID、模糊控制、水泵頻率控制等較複雜的運算。

1. 新增 **演算法** 節點，在下拉選擇演算法
2. 依演算法的輸入埠接上點位或常數；變參演算法可設定 **數量**（每組一套輸入 / 輸出）
3. 有預設參數的演算法，拖入時會自動在左側生成常數節點並接好線，點開即可修改整定值

### 演算法狀態

演算法回傳結果時會附帶狀態，Engine 依嚴重度處理：

| 嚴重度 | 例 | 處理 |
|--------|----|------|
| Info | OK、WARMUP | 結果照常往下傳 |
| Warning | INPUT_OUT_OF_RANGE、SATURATED | 結果照常往下傳，邊線變橘色並寫事件記錄 |
| Error | DIVIDE_BY_ZERO、INPUT_MISSING、NUMERIC_OVERFLOW、API_CALL_FAILED、INTERNAL_ERROR | 該輸出埠的下游不評估、寫入節點本輪不寫，邊線變紅並寫事件記錄 |

狀態由正常轉異常時寫一筆事件記錄，恢復時標記恢復；連續相同狀態不重複寫。

### 演算法檔案放在哪裡

| 位置 | 用途 |
|------|------|
| `C:\JOULARIS\Engine\App\Algorithms\` | Engine 實際執行的演算法（`.py` 與 `.cs`，可依分類放子資料夾） |
| `C:\JOULARIS\Web\App\Algorithms\` | Web 流程圖編輯器列出演算法清單時讀取的副本 |

Python 演算法由 Engine 自動啟動的本機演算法服務（`127.0.0.1:8100`）執行，使用 `Engine\App\PythonRuntime\` 內附的 Python，目標機不需另裝 Python。

在現場新增或修改演算法：

1. 把演算法檔放到 `Engine\App\Algorithms\` 與 `Web\App\Algorithms\` 的同一相對位置
2. 確認檔頭的 `@algorithm`、`@inputs`、`@outputs` 等標記正確（流程圖的輸入 / 輸出埠依此產生）
3. 重啟 Engine 服務 `JoularisEngine`，流程圖編輯器重新整理後即可看到

> ⚠️ 注意：Release 包升級時，演算法資料夾內與包內同名的檔案會被新版覆蓋。在現場修改過的演算法請一併提交回原始碼，否則下次升級會被蓋掉。

> 💡 提示：若流程圖的演算法清單數量與資料夾內檔案對不上，先確認 Web 讀到的是 `Web\App\Algorithms`，並檢查機器上是否殘留其他舊部署的 Algorithms 資料夾。

## 複製邏輯 / 資料夾

新增同型設備時，可整條邏輯或整個資料夾複製：

1. 在邏輯清單對來源項目按右鍵 → **複製**
2. 對目標資料夾按右鍵 → **貼上**（貼為其子項），或在清單空白處右鍵 → **貼到根層**
3. 複製出的項目名為「原名 - 複製」；資料夾會連同所有子項一起複製
4. **所有點位綁定都已清空**、複製出的邏輯一律為停用；計時秒數、常數、演算法參數完全保留
5. 逐一重綁點位、儲存，再啟用

> ⚠️ 注意：畫布上 Ctrl+C / Ctrl+V 複製節點會**保留**綁定；清單右鍵複製會**清空**綁定。

## 搬移與停用

- 清單項目可拖曳搬移到其他資料夾或調整順序
- 搬進已停用的資料夾時會提示：其中所有邏輯會一併停用（Engine 立即停止執行）

## 常見狀況

| 狀況 | 原因 / 處理 |
|------|------------|
| 儲存時提示「版本衝突，將重新載入最新資料」 | 另一個分頁或使用者剛儲存過同一條邏輯，重新載入後再修改 |
| 邏輯沒有動作 | 確認邏輯與上層資料夾都已啟用；Engine 剛重啟的前 60 秒不寫入；上游點位是否 Bad |
| 讀取歷史值的節點一直 Bad | 指定時間前後 5 分鐘內沒有正常歷史資料（新點位、超過保留期間） |
| 演算法節點 API_CALL_FAILED | Engine 連不上 Python 演算法服務，檢查 Engine log 與 `PythonRuntime` 資料夾 |
| 寫入節點沒寫出去 | 授權失效時採集暫停；點位為唯讀；值超限；或該點位正處於手動控制 |
