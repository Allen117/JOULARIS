## 一、目的與範圍

**第一性原理**：稽核員只問一件事 —「你知不知道自己產品裡有哪些已知弱點，知道之後多久修掉，修了怎麼證明」。本程序就是回答這三問的最小閉環：**掃 → 登錄 → 修 → 重掃 → 留證**。

- **適用對象**：ScadaEngine 產品（Engine、Web、Common、Algorithm、LicenseBridge、Tests）及其隨包發佈的 Python 執行環境與前端第三方函式庫。
- **排除**：`ScadaEngine.ModbusServer`（對外 Modbus TCP Gateway）。理由：屬內部工具、非交付產品一部分（2026-10-15 產品負責人裁定）。若日後納入交付，回到本程序範圍。
- **責任**：產品負責人（Allen）負責核准修補時限與風險接受；開發者負責執行掃描與修補。

## 三、掃描方法與工具

每一層用一個工具，全部免費、可離線留存報告。指令皆在 repo 根目錄執行。

| 層次 | 工具 | 指令 | 產出 |
|---|---|---|---|
| SCA .NET | `dotnet list package --vulnerable`（NuGet 官方 advisory 資料庫） | `dotnet list <proj>.csproj package --vulnerable --include-transitive` 逐專案 | 文字報告 |
| SCA Python | `pip-audit`（PyPI Advisory DB + OSV） | `PythonRuntime\python.exe -m pip freeze --all > freeze.txt` → `pip-audit -r freeze.txt --no-deps --format json` | JSON |
| SCA 前端 JS | `retire.js` | `npx retire --path ScadaEngine.Web/wwwroot --outputformat json` | JSON；retire 未收錄的函式庫（如 SheetJS）人工比對 NVD |
| SAST | .NET 內建安全分析器（CA2100 / CA3xxx / CA5xxx） | `dotnet build ScadaEngine.sln -p:AnalysisMode=AllEnabledByDefault -p:AnalysisLevel=latest` 後過濾 `warning CA(2100\|3\d{3}\|5\d{3})` | build log |
| DAST | OWASP ZAP（需 Java） | 對開發實例 `http://localhost:5038` 跑 Baseline + 登入後 Full Scan | HTML 報告 |
| 主機層 | Nessus Essentials 或 OpenVAS | 掃部署主機全埠 | 工具報告 |

**產出保存**：每輪掃描在本文件 §7 新增一節，原始輸出放 §10 附錄或 `docs/security-scans/<日期>/`（大檔）。檔名帶日期，不覆蓋舊輪。

**排除規則**：報告中屬 `ScadaEngine.ModbusServer` 的項目一律剔除（§1）。

## 四、頻率、嚴重度與修補時限

**頻率**：
- 每季一次（1 / 4 / 7 / 10 月）
- 每次功能版（版本號 A+1）Release 前一次
- 重大 CVE 公告（影響 ASP.NET Core、SqlClient、MQTTnet、MailKit、FluentModbus、OPC UA SDK）時加掃一次

**嚴重度**（以 advisory 的 CVSS 為主，依本系統可達性調整一級）：

| 等級 | CVSS | 修補時限 | 備註 |
|---|---|---|---|
| Critical | 9.0–10 | 7 天內 | 可遠端未認證利用且影響控制面 |
| High | 7.0–8.9 | 30 天內 | |
| Medium | 4.0–6.9 | 90 天內 | |
| Low | < 4.0 | 下一功能版 | |

**調整原則**：套件弱點若在本系統中「該 API 路徑不會接觸不受信任輸入」，可降一級並在登錄表註明理由（§8 的「調整理由」欄）；不可降兩級以上，不可降為「不處理」（那是風險接受，走 §6）。

## 五、處置流程

1. **登錄**：每個弱點給 `VUL-YYYY-NNN` 編號寫入 §8，記來源、元件、CVE、嚴重度、修復版本。
2. **修補**：升級套件或改碼，commit 訊息 body 帶 `VUL-YYYY-NNN`，版本號依 CLAUDE.md 規則提 B+1。
3. **重掃**：修補 commit 後重跑該層工具，確認該項消失。
4. **關閉**：§8 狀態改「已關閉」，填 commit hash 與重掃日期。
5. **證據鏈**：稽核時從 §8 的 VUL 編號 → `git log --grep VUL-2026-001` → 該 commit diff → §7 重掃紀錄，四步可追溯。

### 7.3 SCA .NET 明細

| 專案 | 傳遞套件 | 版本 | Advisory | CVE | CVSS | 修復版 | 引入路徑 |
|---|---|---|---|---|---|---|---|
| Engine、Web、Tests | System.Security.Cryptography.Pkcs | 8.0.1 | GHSA-846f-f764-76mx | CVE-2026-84008 | 7.5 High | **8.0.2** | MailKit 4.16.0 → MimeKit；Microsoft.Data.SqlClient 6.1.4 |
| Engine、Web、Tests | System.Security.Cryptography.Pkcs | 8.0.1 | GHSA-2fmv-rv2c-59x7 | CVE-2026-70162 | 5.9 Moderate | **8.0.2** | 同上 |
| Web、Tests | System.IO.Packaging | 6.0.0 | GHSA-f32c-w444-8ppv | CVE-2024-43484 | 8.8 High | **6.0.1 / 8.0.1** | ClosedXML 0.102.2 → DocumentFormat.OpenXml 2.16.0 |
| Web、Tests | System.IO.Packaging | 6.0.0 | GHSA-qj66-m88j-hmgj | CVE-2024-43483 | 8.8 High | **6.0.1 / 8.0.1** | 同上 |

Common、Algorithm、LicenseBridge：無。

**可達性評估**：
- Pkcs 兩則都是「處理攻擊者提供的 CMS / PKCS#7 資料時 CPU 耗盡」。本系統 MailKit 只**寄信**不收信、SqlClient 連 loopback SQL Server，攻擊面實際上很窄，但套件就在出貨包裡，稽核不會接受「用不到」當不修的理由。修法便宜：直接升級。
- System.IO.Packaging 是 hash flooding / 演算法複雜度 DoS，**ClosedXML 解析使用者上傳的 Excel**（Modbus / DB / OPC UA 來源匯入）會走到這條路徑，已登入使用者可上傳惡意 xlsx 打掛 Web。嚴重度維持 High。

**另一項**：CPython 3.11.9（2024-04）是 3.11 系列最後一個提供 Windows binary 的版本，之後的 3.11.x 僅有原始碼安全修正，embeddable zip 拿不到。要持續吃到直譯器層的修補，需把 `SetupPythonRuntime.ps1` 的 `$PythonVersion` 升到 3.12 或 3.13 系列。
