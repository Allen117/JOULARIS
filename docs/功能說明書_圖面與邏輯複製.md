# 功能說明書：圖面與邏輯複製（樹層級複製貼上）

## 1. 功能概述

現場新增一台同型設備（第 3 台冰機、第 2 組空調箱）時，監控畫面與控制邏輯的**版面、顏色、尺寸、計時參數幾乎一模一樣，只有點位不同**。本功能提供**樹層級**的複製貼上，讓「整頁 / 整條邏輯 / 整個資料夾」一次複製，複製出來的東西**點位綁定一律清空**，其餘參數完全相同 —— 只要重綁點位就完成新設備的建置。

### 核心能力

| 頁面 | 複製單位 | 遞迴 | 綁定 | 清除執行端 |
|------|----------|------|------|-----------|
| **Designer**（`/Designer`） | 一個頁面 | ❌ 不含子頁 | 全清空 | 前端（複製當下） |
| **LogicFlow**（`/LogicFlow`） | 一條邏輯 / 一個資料夾 | ✅ 資料夾含所有子項 | 全清空 | **後端**（寫入 DB 前） |

- 操作方式：**一律走右鍵選單**，兩邊都**不提供快捷鍵**
- 剪貼簿存 `localStorage`，可跨分頁、重新整理後仍可貼上

---

## 2. 與「元件 / 節點層級複製」的界線（重要）

系統內有**兩層**複製，語意**相反**，別搞混：

| | 元件 / 節點層級（既有） | 樹層級（本功能） |
|---|---|---|
| **操作** | 畫布上 `Ctrl+C` / `Ctrl+V` | 樹上**右鍵選單** |
| **對象** | 選取的元件 / 節點 | 整個頁面 / 整條邏輯 / 整個資料夾 |
| **點位綁定** | **保留** | **清空** |
| **理由** | 局部複製通常就是要沿用同一點位 | 新增同型設備 = 版面照抄、點位重綁 |
| **實作** | `js/designer/widget-core.js`（`_designer_clipboard`）<br>`js/logicflow/canvas.js`（`_lf_clipboard`） | `js/designer/page-clipboard.js`（`_designer_page_clipboard`）<br>`js/logicflow/tree.js`（`_lf_tree_clipboard`） |

> **為什麼樹層級不給快捷鍵**：同一組鍵在畫布上是「複製元件、保留綁定」，在樹上是「複製整頁、清空綁定」。即使用不同組合鍵，現場人員仍可能記混而按錯，而按錯的代價是**靜默拿著別台設備的點位**。右鍵選單每次都要看到文字才點得下去，不存在肌肉記憶按錯的可能，代價只是多一次點擊。

四個剪貼簿 key 彼此獨立，互不覆蓋。

## 3. Designer — 複製頁面

### 3.1 操作

| 右鍵位置 | 選單項目 | 行為 |
|---|---|---|
| 頁面節點 | **複製此頁** | 把該頁（含版面、背景圖、畫布尺寸、所有元件）放進剪貼簿，**複製當下就清綁定** |
| 頁面節點 | **貼上為子頁面** | 貼成該頁的子頁；貼完自動切換並選中新頁 |
| 頁面樹空白區 | **貼上為根頁面** | 貼到根層 |

「貼上」項目在剪貼簿為空時**不顯示**。

### 3.2 只複製單頁，不含子頁

LogicFlow 的資料夾是「容器」，不遞迴就沒意義；Designer 的頁面本身就是內容，子頁通常是**另一組設備**，一起複製反而要刪。

### 3.3 命名

`原名 - 複製`；同層已存在則遞增為 `原名 - 複製 (2)`、`(3)`…（i18n key `designer.page.copy_suffix`）。

### 3.4 清除範圍

保留：位置、尺寸、顏色、字體、標題、文字、單位（`szUnit`）、ON/OFF 標籤、量程（`fMin`/`fMax`）、表格結構與每格樣式、管路節點座標、背景圖。

清空（設為空字串 `''`）：

| 類別 | 欄位 |
|---|---|
| 明確清單 | `szPointName`、`szRunName`、`szFaultName`、`szModeName`、`szFreqName`、`szLoadName`、`szChwOutName`、`szWaterTempName`、`szStartStopName`、`szFreqSetName`、`szSetTempName`、`szCircuitName`、`szScheduleName`、`szBindMode` |
| 前綴規則 | `/^szSid/`（`szSid`、`szSidRun`、`szSidFault`、`szSidMode`、`szSidFreq`、`szSidLoad`、`szSidChwOut`、`szSidWaterTemp`）<br>`/^szCid/`（`szCid`、`szCidStartStop`、`szCidFreqSet`、`szCidSetTemp`） |

刪除（`delete`，JSON 內不留痕）：`nCircuitId`、`nScheduleId`、`szMetric`。

**表格 `arrCells[ri][ci]` 每一格**遞迴套用同一組規則 —— 表格每格都可獨立綁點位，漏清一格就是靜默保留舊點位。

> `szBindMode`（管路綁定模式）必須一併清空：留著 `'di'`/`'analog'` 而 SID 被清空，執行期 `scadapage/render.js` 的 `updatePipe` 會直接 return，管路卡在「永遠停止」的半狀態。清成 `''` 才回到「未綁定 = 純裝飾固定流動」的正確預設。

### 3.5 啟動自檢（防漏）

`widget-defs.js` 的 `auditDesignerBindingKeys()`（由 `index.js` 啟動時呼叫）會掃描 `WIDGET_DEFS` 所有 `defaultProps`，凡 key 名稱含 `Sid` / `Cid` / `CircuitId` / `ScheduleId` 卻不在清單也不在前綴規則涵蓋範圍 → `console.warn`。

純硬編清單日後一定會漏（新增 widget 時沒人記得回來改），而漏掉就是**靜默保留舊點位**。自檢讓漏的當下在 console 就喊出來。

## 4. LogicFlow — 複製邏輯 / 資料夾

### 4.1 操作

| 右鍵位置 | 選單項目 | 行為 |
|---|---|---|
| 樹節點 | **複製** | 把該節點放進剪貼簿（只存 `{ id, name }`，實際複製在貼上時才發生） |
| 樹節點 | **貼上** | 目標為**資料夾** → 貼為其子項；目標為**邏輯** → 貼到該邏輯所在層 |
| 樹空白區 | **貼到根層** | 貼到根層 |

既有 hover 按鈕列（新增資料夾 / 新增邏輯 / 啟用 / 改名 / 刪除）**不動**，不加第 6 顆鈕。

### 4.2 遞迴與狀態

- 複製**資料夾** → 其下所有子資料夾與邏輯**全部遞迴複製**，階層與排序一致
- 複製**邏輯** → 流程圖的所有節點、連線、座標、演算法、常數、計時秒數、counter preset 一模一樣
- 複製出的**邏輯節點一律 `IsEnabled = 0`（停用）**，資料夾維持啟用
  - 點位還沒綁，這是半成品。啟用等於讓 Engine 把一條不完整的邏輯排進執行清單
  - 與「新增邏輯預設停用」（`CreateNodeAsync`）的既有慣例一致
- 新 Diagram 的 `Version` 從 0 起算
- 貼上的根節點命名同 Designer：`原名 - 複製` / `原名 - 複製 (2)`（i18n key `logicflow.copy.suffix`）；`Name` 欄位為 `nvarchar(100)`，超長截斷

### 4.3 清除範圍（在**後端**執行）

`ScadaEngine.Web/Services/LogicFlowDiagramBindingStripper.cs` 清除 `DiagramJson` 內每個節點的：

```
sid / pointName / unit / scheduleId / scheduleName /
histEnabled / histOffsetMinutes / fMin / fMax
```

保留：`id`、`type`、`x`、`y`、`operator`、`constValue`、`timerDelay`、`timerHold`、`presetValue`、`cuMinIntervalMs`、`algoInputs`、`inputCount`、`height`，以及 `edges[]` 全部內容（id / source / sourcePort / target / targetPort 原封不動）。

**為什麼一定要在後端做**：綁定清除是**正確性**要求而非顯示偏好。若留給前端在使用者開啟該邏輯時才清，那麼「複製資料夾 → 直接啟用其中一條從沒開啟過的邏輯」就會拿著來源點位跑 —— 對 `output` 節點等於**寫進別台設備的 Modbus 暫存器**。必須在資料落地前就清乾淨。

**`fMin` / `fMax` 也清**：這是 picker 從點位帶入的量程快照，用於 `output` 的超範圍判斷與變參演算法自動注入。留著舊點位的量程，新點位綁上去後判斷會錯，而且畫面上看不出來。

> ⚠️ **既有小不一致**：畫布節點右鍵的「清除綁定」**沒有**清 `fMin`/`fMax`。本功能只在複製路徑清，未順手改既有選單行為（避免擴大 diff）。

**解析失敗的處理**：`DiagramJson` 為 null / 空字串 / 無法解析 / 根不是物件時，回傳空白流程圖 `{"nodes":[],"edges":[]}`。解析不了就無法保證清乾淨，原樣傳回等於把綁定照抄過去 —— 寧可給空白畫布。

### 4.4 未綁定徽章

`input` / `output` / 接點節點若無 `sid`（接點另需無 `scheduleId`），畫布上顯示灰色虛線邊框的「⃠ 未綁定」徽章（`.unbound-badge`）。

刻意用低調灰字而非紅色警示 —— 開發中正常存在的空白接點（純邏輯控制、由 ctrl 埠驅動）也會命中這個條件，一片紅會變成雜訊。

## 5. 路由 / API

| 方法 | 路由 | 說明 | 認證 |
|------|------|------|------|
| POST | `/LogicFlow/api/tree/{nId}/copy` | 複製節點到指定父層，回 `{ id }` | Engineer |
| PUT | `/LogicFlow/api/tree/{nId}/move` | **拖曳搬移**節點到指定父層 + 位置（只能放進資料夾 / 根層；停用資料夾連動停用子樹），回 `{ success, disabledCount }` → [功能說明書_階層樹拖曳搬移.md](功能說明書_階層樹拖曳搬移.md) | Engineer |

Request body：

```json
{ "targetParentId": 12 }   // null = 貼到根層
```

回應：

- `200 { "id": 34 }` — 新節點 Id
- `404 { "success": false, "message": "..." }` — 來源不存在，或目標父層不是資料夾

Designer 端**純前端**，複製貼上不打任何 API；貼出的新頁按工具列「儲存」時，隨整包設計一起走既有 `POST /Designer/Save`。

## 8. 已知限制

- **樹容器空白區**：`#treeContainer` 以 CSS `min-height: 100%` 撐滿卡片可捲區，末項下方的空白才吃得到右鍵事件。
- **剪貼簿來源被刪除**：LogicFlow 剪貼簿只存 `{ id, name }`，貼上時才打 API。若來源已在別的分頁被刪除，貼上會提示「來源項目已不存在」並清掉剪貼簿。
- **背景圖撐爆 localStorage**：Designer 頁面資料含 `szBgDataUrl`（背景圖 base64），大圖可能超過 5MB 配額。發生時自動退回「不含背景圖」版本並 toast 提示；再失敗則提示複製失敗。
- **同時開兩個 Designer 分頁編輯會互相覆蓋**：`nPageIdCounter` 各分頁獨立，兩邊都貼上再各自儲存時，後存的會整包覆寫先存的。這是既有 Save 語意（整包覆寫），非本功能引入。
- **大資料夾複製**：逐節點 INSERT。數十條邏輯的資料夾交易會偏長，目前未做批次優化。
- **綁定欄位清單兩處維護**：前端 `js/logicflow/canvas.js` 的「清除綁定」選單與後端 `LogicFlowDiagramBindingStripper` 各有一份清單。未來新增節點綁定欄位時可能只改一邊 —— 兩處都加了註解互相指名，且單元測試的預期清單即為書面真相。
