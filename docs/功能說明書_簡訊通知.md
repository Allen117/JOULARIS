# 功能說明書：簡訊通知（GSM 簡訊盒 + 4G SIM）

## 1. 功能概述

在**無網際網路**的現場（Line / Email 皆不可用）仍能發送警報通知：
Engine 透過序列埠簡訊盒（GSM/4G Modem + SIM 卡）直接發送 SMS 至多支手機號碼。

- 與 Line / Email 並列為第三種通知通道，UI 在 **AlarmSetting 第 4 個 tab「簡訊通知」**
- 每個號碼**獨立**設定接收嚴重度（MaxSeverity）與語言（zh-TW / en），與 Line/Email 完全分離
- **不綁簡訊盒廠牌**：只用 3GPP TS 27.005 標準 AT 指令，任何支援標準 AT 的 USB / RS-232 GSM modem 皆可
- **COM port 自動偵測**：`ComPort:"auto"` 時啟動掃描所有 COM port 以 AT probe 找出 modem，failover 自動重掃
- 警報**觸發 + 恢復**皆通知（恢復可用 `SendRecovery` 開關關閉以省費）

### 支援的簡訊盒條件（採購參考）

1. 序列埠介面（USB 虛擬 COM 或 RS-232）
2. 支援標準 AT 指令（3GPP TS 27.005）：`AT+CMGF=1`（文字模式）、`AT+CSCS="UCS2"`、`AT+CMGS`
3. 4G 機種需支援 SMS over LTE 或自動 fallback（一般皆支援）

## 2. 架構與資料流

```
AlarmMonitorService 觸發/恢復
    ↓ SmsNotificationService.NotifyAsync / NotifyClearedAsync
severity 路由（SmsNotifyTargets.MaxSeverity >= 警報嚴重度）
    ↓ 限流視窗（每號碼 RatePerMinute；Critical 繞過）→ 超量進 buffer，視窗結束發摘要簡訊
    ↓ DailyQuota 每日硬上限（含 Critical；0=不限）
背景佇列（Channel，上限 200 件；序列埠每封 5~10 秒，絕不阻塞警報主流程）
    ↓ SmsModemClient（ISmsTransport 唯一實作）
AT+CMGS（UCS2 編碼）→ 簡訊盒 → 電信網路 → 手機
    ↓ NotifyDeliveryLogger
EventLog（EventType=3, NotifyChannel='Sms'）
```

### 序列埠獨占 → Web 一律經 MQTT 代理（與 Line/Email 的本質差異）

序列埠被 Engine 開啟後 Web 無法直接操作，因此：

| Topic | 方向 | 用途 |
|---|---|---|
| `SCADA/Sys/Sms/Cmd`（Retain=false）| Web → Engine | `{"action":"test","phoneNumber":"..","label":"..","language":".."}` 測試發送；`{"action":"rescan"}` 重掃 port |
| `SCADA/Sys/Sms/Status`（Retain=true）| Engine → Web | 連線狀態 / port / 訊號 CSQ / SIM 狀態 / 今日已發封數 / 最近測試結果；狀態變化即發 + 每 60 秒定期發 |

Web 端 `MqttRealtimeSubscriberService` 訂閱 Status 存入 `SmsStatusCache`（Singleton），
`GET /api/sms-status` 直接透傳 JSON 給前端狀態卡（簡訊 tab 顯示時每 10 秒輪詢）。

## 3. COM port 自動偵測（SmsModemClient）

1. `ComPort:"auto"`：`SerialPort.GetPortNames()` 列出候選 → 逐 port × baud（115200 → 9600，或手動指定）
2. 每個 port 送 `AT` 等 `OK`（2 秒 timeout）→ 有回應再驗 `AT+CPIN?`：
   - `READY` → 是插了 SIM 的 modem port（USB modem 常虛擬多個 port，只有這步能排除 diagnostic/NMEA port）
   - `SIM PIN` 且設定有 `SimPin` → `AT+CPIN="xxx"` 解鎖後重驗
3. 設 `ATE0`（關 echo）、`AT+CMGF=1`（文字模式）、`AT+CSCS="UCS2"` → 全部成功即鎖定該 port 持續持有
4. 發送**連續失敗 2 次**或健康檢查（每 60 秒 `AT+CSQ` / `AT+CPIN?`）無回應 → 關 port 標記斷線，下輪自動重掃（涵蓋 USB 拔插）
5. 手動指定 `"COM3"` 則跳過掃描只試該 port

## 4. 訊息編碼與長度限制

- 一律 UCS2（UTF-16BE hex）：中英文通用；`AT+CMGS` 的**電話號碼與內文都要 UCS2 編碼**
- **單封上限 70 個 UTF-16 字元**（UCS2 硬限制）；超長截斷為 69 字 + `…`（不切斷 surrogate pair）
- 模板刻意精簡（`Resources/notification.{zh-TW,en}.json` 的 `notify.body.*.sms` 系列）：
  - 觸發：`[警報-{severity}] {time} {message}`（時間格式 MM/dd HH:mm 省字數）
  - 恢復：`[恢復] {time} {message}`
  - 摘要：`[警報摘要] 近1分鐘共{count}則：緊急{critical} 高{high} 中{medium} 低{low}`
- 不使用 BMP 外 emoji（🚨 等會佔 2 字元且部分 modem/手機顯示異常）

## 5. 費用防護（三層）

| 層 | 機制 | 預設 |
|---|---|---|
| 每分鐘限流 | 每號碼獨立 1 分鐘滑動視窗，超量進 buffer、視窗結束合併為一封摘要簡訊；Critical (severity=0) 繞過 | 10 封/分 |
| 每日硬上限 | `DailyQuota`，達標即停發（**含 Critical**）+ 寫 EventLog 告警，跨日自動歸零；UI 可自行調整，0 = 不限制 | 100 封/日 |
| 恢復通知開關 | `SendRecovery=false` 時只發觸發不發恢復（約省一半費用） | 開 |

另有「測試發送」同號碼節流（`TestSendThrottleSeconds`，預設 10 秒，Web 端擋）。

## 6. 設定

### SmsSetting.json（開發 repo `ScadaEngine.Engine/Setting/`，無機密、進版控；生產機 **`C:\JOULARIS\Shared\`**，Engine 與 Web 共用一份）

路徑由 Common `SharedSettingLocator` 解析（`..\..\Shared` → 本機 `Setting` → 開發 repo），Engine 讀、Web 讀寫同一份；升級由 Install.bat 自動從舊佈局 `Engine\App\Setting` 搬到 `Shared\`。見 [架構.md §共用設定檔解析順序](架構.md#共用設定檔解析順序)。

```json
{
  "EnableNotification": false,   // 總開關
  "ComPort": "auto",             // "auto" 或 "COM3"
  "BaudRate": 0,                 // 0 = 自動嘗試 115200 → 9600
  "SimPin": "",                  // SIM 未設 PIN 留空（建議關 PIN）
  "RatePerMinute": 10,
  "DailyQuota": 100,             // 0 = 不限制
  "SendRecovery": true,
  "TestSendThrottleSeconds": 10
}
```

Web「簡訊」tab 存檔後 Web 發 MQTT `SCADA/Sys/Notify/Reload`（`{"file":"SmsSetting.json","requestId":"…"}`），Engine `NotifySettingReloadSubscriber` 重讀 `Shared\SmsSetting.json` → `SmsNotificationService.ReloadSettingAsync` → `SmsModemClient.ReloadAsync`（關舊 port、依新 ComPort / BaudRate 重掃；停用則只關 port、停健康檢查）→ 回 `SCADA/Sys/Notify/Status`，Web 存檔回應直接顯示「Engine 已套用 / 未回應 / 套用失敗」。**不必重啟 Engine**；JSON 壞掉或重掃失敗保留舊設定並寫 EventLog（EventType=3）。號碼增刪改則走 DB 60 秒快取。

### 資料表 SmsNotifyTargets（DatabaseSchema.json 自動建）

| 欄位 | 型別 | 說明 |
|---|---|---|
| Id | int PK identity | |
| PhoneNumber | nvarchar(32) | 國際格式（+886912345678）或本地格式（0912345678） |
| Label | nvarchar(100) | 顯示名稱 |
| MaxSeverity | tinyint = 3 | 0=只收 Critical, 1=+High, 2=+Medium, 3=全收 |
| Language | nvarchar(10) = 'zh-TW' | 'zh-TW' / 'en' |

路由模型照 Line（純 severity，per-號碼），**不做** Email 式規則綁定。

## 7. 主要類別

**Engine：**

| 類別 | 職責 |
|---|---|
| `ISmsTransport` | 傳輸抽象（路由層與硬體解耦，未來可加 HTTP 簡訊閘道實作） |
| `SmsModemClient` | 序列埠 + AT 指令：掃描/probe、發送、健康檢查、狀態事件（獨占持有 port，SemaphoreSlim 序列化） |
| `SmsAtHelper` | 純函式：UCS2 編碼、70 字截斷、AT 回應/CSQ/CPIN 解析（單元測試鎖定） |
| `SmsNotificationService` | 路由、限流、摘要、每日上限、背景佇列、EventLog 摘要 |
| `SmsTargetRepository` | SmsNotifyTargets 唯讀 + 60 秒快取 |
| `SmsMqttBridge` | 訂閱 Cmd / 發布 Status（BackgroundService） |

**Web：**

| 類別 | 職責 |
|---|---|
| `SmsTargetService` | SmsNotifyTargets CRUD（Scoped） |
| `SmsSenderConfigService` | SmsSetting.json 讀寫（Singleton） |
| `SmsCommandPublisher` | 發 MQTT Cmd（雙註冊 Singleton + HostedService） |
| `SmsTestSendService` | 測試發送 throttle + 發 Cmd（Singleton） |
| `SmsStatusCache` | Status retained JSON 快取（Singleton，MqttRealtimeSubscriberService 更新） |

Web API：`~/api/sms-targets`（GET/POST/DELETE、`/{id}/toggle`、`/{id}/test`）、`~/api/sms-config`（GET/POST）、`~/api/sms-status`（GET）、`~/api/sms-rescan`（POST）。

## 8. EventLog 摘要格式

沿用 `NotifyDeliveryLogger`（EventType=3、Severity=3）：

- `NotifyChannel='Sms'`、`NotifyStatus` 0=AllSent 1=PartialFailed 2=AllFailed 3=RateLimited 4=NoTarget 5=Disabled
- 摘要範例：`Sms 通知: 號碼 3 個，成功 2、失敗 1（王主任）、達每日上限略過 0`
- 達每日上限時另寫一筆 `_system` RateLimited：`已達每日簡訊上限 100 封，今日停止發送（明日自動恢復）`
- 測試發送結果也寫 EventLog（SID=`_system`）

## 9. 已知限制

1. **無送達保證**：EventLog 記的是「modem 接受發送（+CMGS OK）」，非「手機已收到」；不實作 delivery report（+CDS）
2. **不支援長簡訊串接**：>70 字截斷（不做 PDU concatenated SMS）；警報模板已刻意精簡
3. **不做接收**：僅發送，無簡訊回覆/指令功能
4. 電信商對短時間大量發送可能封鎖 SIM — 限流參數請保守設定
5. 開發環境無實機時，AT 對答邏輯以單元測試 + 虛擬 COM port 驗證；端到端發送需實機驗收
