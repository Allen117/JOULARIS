# 功能說明書 — 電費設定

> 路由：`/TariffSetting`（EMS 體系，能管設定選單下）
> 完全比照台電「各類電價表」（114 年 10 月 1 日起實施版），涵蓋全部 20 種方案，價目/時段可編輯、可還原台電預設。
> **已含電費計算**（2026-07）— 選定採用方案後 Web 背景服務逐時計價寫入 `ElectricityCostHourly`，EMS 首頁「電費狀態」卡呈現本期各時段 kWh 與流動電費；本頁提供「重新計算電費」回溯。詳見下方 §電費計算。

---

## 功能總覽

- **方案選擇**：用電類別（表燈住商 / 低壓電力 / 高壓電力 / 特高壓電力）→ 電價方案 兩層下拉，任一方案可「設為採用方案」
- **三種方案型態，一套統一渲染**：
  - `progressive` 累進級距（表燈非時間電價 3 種）：級距邊界 + 夏月/非夏月每度單價可編輯
  - `flat` 單一費率（低壓非時間電價）：基本電費 + 夏月/非夏月每度單價
  - `tou` 時間電價（其餘 16 種）：基本電費表（按戶/按瓩 × 夏/非夏）+ 流動電費時段表（平日/週六/週日及離峰日 × 尖峰/半尖峰/離峰 × 夏/非夏 → 時間區間組 + 單價）
- **夏月起訖**（月-日）可編輯：表燈/低壓預設 06-01～09-30；高壓/特高壓預設 05-16～10-15；EV 方案 06-01～09-30
- **簡易型加價**：每月總度數超過門檻（預設 2,000 度）每度加價（預設 1.04 元）可編輯
- **區間名稱可編輯**：留空時顯示 i18n 預設名（尖峰/半尖峰/離峰）
- **還原台電預設**：單一方案還原，不影響其他方案
- zh-TW / en 雙語；權限管理（AccountSetting）可單獨授權

## 方案清單（20 種）

| 類別 | 方案 |
|---|---|
| 表燈（住商） | 累進 住宅用 / 非營業用 / 營業用；簡易型 TOU 二段/三段；標準型 TOU 二段/三段 |
| 低壓電力（<100 瓩） | 非時間電價；TOU 二段/三段；電動車充換電設施 |
| 高壓電力（≥100 瓩） | TOU 二段；三段（尖峰固定 / 尖峰可變動）；批次生產；電動車充換電設施（95% 註記） |
| 特高壓電力（≥1,000 瓩） | TOU 二段；三段（尖峰固定 / 尖峰可變動）；批次生產 |

排除「包制電價」（路燈/警報器按戶包月，非電表計度）。

## 資料儲存

| 位置 | 內容 |
|---|---|
| `ScadaEngine.Web/Setting/tariff-taipower-defaults.json` | 台電預設 seed（唯讀，隨程式部署；csproj `CopyToOutputDirectory`）。台電調價時**只改此檔** |
| `SystemSettings`（SettingKey = `electricity_tariff`） | 使用者版整份 JSON（含採用方案 + 全部方案），整份載入整份儲存 |

讀取邏輯（`TariffSettingService.GetConfigAsync`）：

1. DB 無值 → 回 seed（不落 DB，第一次儲存才寫入）
2. DB 有值 → 以 DB 為準；seed 中新增的方案（未來台電新版）以 `szPlanId` 比對自動補齊
3. DB JSON 損毀 → log error 後回 seed（不覆寫 DB）

## 資料模型（JSON 結構）

```jsonc
{
  // 【衍生欄位】存檔時由後端算 SelectPlanForDate(config, 今天) 寫入，供 UI badge 與相容用；
  // 唯一真相是 adoptions，勿直接改這裡
  "szActivePlanId": "hv_tou2",
  // 【唯一真相】採用時間軸 — 哪天起改用哪個方案（見下方「方案版本與採用時間軸」）
  "adoptions": [
    { "szEffectiveDate": "2025-01-01", "szPlanId": "hv_tou2" },
    { "szEffectiveDate": "2026-06-01", "szPlanId": "my-flat-01" }
  ],
  "plans": [{                           // 方案【目錄】：台電 seed 各類別 + 使用者自建，彼此並存
    "szPlanId": "hv_tou2",              // 穩定識別碼 = i18n key 後綴（tariff.plan.{id}）
    "szName": "",                       // 自建方案的顯示名；空 = 用 i18n key（台電 seed 皆空）
    "szCategory": "lighting|lv|hv|ehv|custom",   // custom = 使用者自建
    "szType": "progressive|flat|tou",
    "szSummerStart": "05-16",           // 夏月起訖（月-日，含）
    "szSummerEnd": "10-15",
    "szNoteKey": "tariff.note.batch",   // 備註 i18n key，可 null
    "tiers":    [{ "nFrom": 0, "nTo": 120, "dSummer": 1.78, "dNonSummer": 1.78 }],  // progressive
    "flatRate": { "dSummer": 4.08, "dNonSummer": 3.87 },                              // flat
    "baseFees": [{ "szKey": "regular_kw", "szUnit": "kw", "dSummer": 223.6, "dNonSummer": 166.9 }],
    "flowRates": [{ "szDayType": "weekday|sat|sun_offday", "szSeason": "summer|nonsummer",
                    "szPeriod": "peak|semipeak|offpeak", "szName": null,   // null = 用 i18n 預設名
                    "ranges": ["16:00-22:00"], "dPrice": 9.39 }],
    "surcharge": { "nOverKwh": 2000, "dPrice": 1.04 }   // 簡易型限定，可 null
  }],
  // 契約容量歷史（2026-10 新增）— 哪天起各契約別訂多少 kW；契約容量最佳化回測逐計費月取當時有效值
  "contracts": [
    { "szEffectiveDate": "2025-01-01", "kw": { "regular_kw": 1500, "sat_semipeak_kw": 200 } }
  ]
}
```

- `baseFees.szKey` 固定詞彙（i18n key = `tariff.basefee.{szKey}`）：`per_household` / `per_household_1p` / `per_household_3p` / `device_household` / `device_kw` / `demand_household` / `regular_kw` / `nonsummer_kw` / `semipeak_kw` / `sat_semipeak_kw` / `offpeak_kw`
- `baseFees` 的 `dSummer` / `dNonSummer` 為 `null` 表該季不適用（UI 顯示 —，如非夏月契約無夏月價）
- 時間區間 `"HH:mm-HH:mm"`：訖 `24:00` 合法；**起 > 訖 = 跨午夜**（如 `22:30-07:30`）。UI 上訖時選 `00:00` 代表 `24:00`

## 驗證規則（前後端同規則，後端為準）

- **TOU**：每（日別 × 季節）組的時段聯集必須**覆蓋 00:00–24:00 且互不重疊**（跨午夜拆兩段計）；三日別 × 兩季節共 6 組皆須存在
- **累進**：級距連續（下一級 nFrom = 上一級 nTo + 1，UI 自動接續）、上限 > 下限、僅最後一級可「以上」
- 單價 ≥ 0；加價門檻 > 0；夏月起訖為合法「月-日」
- 儲存單一方案時 `szCategory` / `szType` 以伺服器既有值為準（防前端竄改）

## 契約容量歷史（2026-10 新增）

電費設定頁「契約容量歷史」區塊：一列 = 生效日（含當日）+ 五個契約別 kW（經常 / 非夏月 / 半尖峰 / 週六半尖峰 / 離峰，依台電電費單填寫）。

- 用途：[契約容量最佳化](功能說明書_契約容量最佳化.md) 回測時，每個計費月取**期別起日**有效的紀錄當作「現行契約」；回測期間契約有變更時逐月套用
- 選版：生效日 ≤ 目標日的最新一筆（`TariffSettingService.SelectContractForDate`）；查無 = 未設定
- 計費範圍：只有採用方案 `baseFees` 內有的契約別才會計費，多填的 key 不影響
- 驗證（前後端同規則）：生效日 `yyyy-MM-dd` 不重複；kW ≥ 0；key 限五個契約別；每筆至少一個契約別 > 0
- 儲存：獨立按鈕「儲存契約容量」→ `POST api/contracts`。存採用時間軸 / 方案時，後端以 DB 現值保留 contracts（避免只送兩個欄位的舊前端把它清空）
- 本頁的流動電費計算**不使用**契約容量（EMS 電費卡仍註明「不含基本電費」）

## 電費計算（2026-07 新增）

### 資料流

```
EnergyLeafHourly（Engine 每小時 XX:02 寫入，每葉子每小時 kWh 增量）
        │  Web ElectricityCostAggregationService（每小時 XX:05 觸發）
        ▼
ElectricityCostHourly（一列 = 葉子 SID × 小時 × 時段；ElectricityCostService 落段計價）
        │  查詢時遞迴 CTE 取 EffectiveSign 加總（同用電報表模式）
        ▼
GET /EMS/api/electricity-cost → EMS「電費狀態」卡（本期 = BillingPeriods 期別）
POST /ElectricityCostReport/api/query → 電費報表（見 docs/功能說明書_電費報表.md）
```

- **逐日依採用時間軸選版計算**：每一天各自套「該日生效的方案」（`SelectPlanForDate`）。某日在時間軸上沒有任何採用紀錄 → 該日不計價
- 背景服務每小時 **重算近 48h rolling window**（DELETE + INSERT 覆蓋，吸收 Engine 回填）；啟動時 catch-up 近 N 天（`appsettings.json` `ElectricityCost:CatchUpDays`，預設 7）
- 更早的歷史靠本頁「重新計算電費」按鈕回溯（可選起訖日，區間上限 366 天防呆），或勾「全量重算」由前端自動分段跑完整個時間軸

> ⚠️ **無方案的日子會被清空**：重算是「整段 DELETE 再寫回」，某日查無適用方案時不產列 → 該日舊列被刪且不重寫。
> 這是刻意的 —— 時間軸上沒採用方案的日子，留著舊方案算出的金額等於讓錯誤數字無聲存活。
> **可完整還原**：本表是衍生資料，來源 `EnergyLeafHourly` 未被動到，補上該期間的採用紀錄後重算即可（含 Kwh 快照）。
> 整段區間都查無方案時會直接回 `no_active_plan` 並**不動任何資料**。

### 方案版本與採用時間軸

台電 seed 的 20 個方案是**不同用戶類別並存的目錄**（表燈/低壓/高壓/特高壓），彼此不是版本關係。
因此電費不像水費「每個方案帶生效日」，而是**目錄 + 時間軸**兩層：

- `plans[]` = 可選用的方案目錄（seed + 自建），無時間概念
- `adoptions[]` = 時間軸，一列 = 「從某日起改用某方案」
- 選版 = `adoptions` 中生效日 ≤ 目標日的**最新一筆** → 取其 `szPlanId` 查 `plans`；查無則該日不計價

**歷史不被追溯改寫**：改費率或新增採用紀錄後，既有 `ElectricityCostHourly` 不動（每列已快照當時的 `PlanId`），要更新得主動重算。

**升級相容**：舊設定只有 `szActivePlanId` 而無 `adoptions` 時，讀取時自動在記憶體補一筆 `2000-01-01` 生效紀錄
（`MigrateLegacyActivePlan`）。生效日極早 → 任何歷史日期都選到同一方案 → **歷史電費數字完全不變**，升級無感。
首次按下任何儲存才會把 `adoptions` 實際寫進 DB。

**狀態卡（EMS 電費卡 / 本頁頂部累計卡）選版**：依「本期起日」選方案；若本期中途才**首次**採用（生效日晚於本期起日 → 起日查無方案），退回「今日」適用的方案，避免報表已有金額、卡片卻顯示「尚未選擇電費方案」。tou / flat 金額直接加總 `ElectricityCostHourly`（已逐日選版）不受影響；progressive 級距以整期 kWh 套用，含生效日前的度數，為參考值。

⚠️ **換方案的生效日建議對齊期別起日**：若同一月結期別內跨了兩個 progressive 方案版本，累進級距會對每個 `PlanId` 的 kWh 各自從第一級起算，總額低於「整期合併套級距」。這是報表端 by-`PlanId` 聚合的既有語意。

### 自建方案（custom 類別）

- 在方案選單新增第五類「自訂」，與台電四類分開列示
- 可新增（三型皆可）/ 複製既有方案再改 / 刪除；**刪除前會擋**：方案仍被任一採用紀錄引用時拒絕
- 只有 custom 方案可指定 `szType` 與 `szName`；台電 seed 方案維持結構性欄位防竄改（`szCategory`/`szType` 以既有值為準）
- custom 方案不在 seed 內，故「還原預設」對其回明確錯誤
- 典型用途：房東「一度五塊」→ 建 flat 方案，`dSummer` 與 `dNonSummer` 都填 5（等同不分季）

### ElectricityCostHourly 表

| 欄位 | 說明 |
|---|---|
| SID + HourStart + Period（複合 PK） | 葉子 × 小時 × 時段；PK 含 Period 使跨時段邊界的小時可拆兩列 |
| Kwh | 該時段分攤 kWh（快照自 EnergyLeafHourly.DeltaKwh，**未套 sign**；邊界非整點按分鐘比例分攤） |
| UnitPrice / Cost | tou/flat = 計算當下費率與金額；**progressive = NULL**（查詢時套級距） |
| PlanId / PlanType / Season | 計算當下方案快照 + 季節（summer/nonsummer 按日判定） |
| Quality | 承 EnergyLeafHourly.Quality（=0 時 DeltaKwh 恆 0 → 電費 0，資料缺口會低估電費） |

### 計價規則

- **季節**：依方案 `szSummerStart/End`（MM-dd 含頭尾）按日判定；起 > 訖視為跨年
- **DayType（tou）**：假日優先於星期 — 日期在 `Holidays` 表 → `sun_offday`；週六 → `sat`；週日 → `sun_offday`；其餘 → `weekday`（假日維護見 [功能說明書_國定假日設定.md](功能說明書_國定假日設定.md)）
- **tou 落段**：該日（日別 × 季節）時段組展開為分鐘區間（跨午夜拆兩段），每小時與區間取交集 → kWh 按分鐘比例分攤（如 07:30 邊界 → 該小時拆兩列各 0.5 權重）
- **progressive**：級距是「月總度數」的函數 → 逐時列只存 kWh（Period=`all`），查詢時取本期累計 kWh 套級距；夏月/非夏月混月以夏月 kWh 占比對每級單價加權（占比法近似）
- **重算語意**：一律以「目前生效方案」費率覆蓋（DELETE 區間 + 重算，7 天一塊分交易）；不做費率版本化

### TariffSetting 頂部累計卡片

頁面頂部「目前累計用電度數 / 目前累計電費」兩張卡片載入時打 `GET api/cost-summary`（= `ElectricityCostService.GetStatusAsync(null)`，主要電表本期），顯示本期累計 kWh 與流動電費，提示列顯示「本期 {期別}・{迴路名}（不含基本電費）」；未選方案或無迴路時維持 `--` 與預設提示。重算成功後自動刷新。

### EMS 電費狀態卡

- 依方案型態自適應：tou（各時段 kWh/電費 + 超額加價列）/ progressive（累計 kWh + 落點級距）/ flat（累計 kWh + 當季單價）
- 可下拉切換迴路（預設主要電表；未設主要電表取第一個根節點）；子迴路依葉子 × EffectiveSign 加總（Sign=-1 迴路電費為負）
- **級距 / surcharge（簡易型超額加價）金額只對根迴路精確**；子迴路以 kWh 占比分攤並標示「估算」badge
- 卡片註記「**不含基本電費**」（契約容量類基本費留後續版本）；今日小計 progressive 無金額（無法歸屬單日）
- 60 秒輪詢；底部顯示「資料計算至 yyyy-MM-dd HH:00」

## i18n 慣例

- 方案/類別/型態/時段別/基本電費項目名稱**不存 JSON**，由識別碼組 i18n key 顯示（`tariff.plan.{szPlanId}` 等）→ 雙語自動切換
- 使用者自訂的區間名稱（`szName`）為 user input，不在 i18n 範圍；留空 = 用 `tariff.period.{szPeriod}` 預設名

## 台電調價 SOP

1. 由台電官網下載新版「各類電價表及計算範例」
2. 更新 `Setting/tariff-taipower-defaults.json` 價目（結構不動）
3. 部署後：未改過的使用者第一次儲存前即看到新價；已自訂的方案不受影響，可按「還原台電預設」取新價

## 後續版本（本版明確不含）

- 基本電費（契約容量 kw 類）計入 EMS 卡 / 電費報表 — 目前只算流動電費；契約容量的需量費回測已由 [契約容量最佳化](功能說明書_契約容量最佳化.md) 提供
- 「尖峰時間可變動」的台電指定 30 日維護介面
- 電價生效日版本化（歷史報表鎖舊價）— 目前重算一律用現行費率

## 已知限制

- 訖時 `00:00` 在 UI 上代表 `24:00`（flatpickr 無法輸入 24:00），全日時段顯示為 `00:00-00:00`
- EV 高壓 95% 折算、指定 30 天加價僅以備註呈現，不參與計算
- 頁面顯示之台電預設價目以 seed 檔為準（114/10/1 版）；台電若調價需更新 seed
- Quality=0 的小時 DeltaKwh 恆 0 → 電費 0，資料缺口會**低估**電費（與用電報表既有行為一致）
- 修改費率/方案/假日後，已算過的歷史區間**不自動重算**，需按「重新計算電費」；重算期間 EMS 卡可能短暫讀到不一致資料
- progressive 夏月/非夏月混月採「夏月 kWh 占比加權」近似，與台電按日數比例分計可能有微小差異
