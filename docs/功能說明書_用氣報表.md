# 功能說明書 — 用氣報表（天然氣表迴路設定 + 用氣報表）

> ⚠️ 本功能處理**累積式天然氣表**（讀數單調遞增的 m³ / Nm³ / 度 氣量表），全體系採 `GasMeter*` 前綴。
> 與 `WaterMeter*`（累積式水表）、`WaterCircuit`（空調水系統冷凍噸 RT）皆**完全無關**，三套平行樹各自獨立。
> 跨模組資料流總覽見 [架構.md](架構.md) §用氣報表與氣費計算。

## 1. 天然氣表迴路設定（/GasMeterSetting，UI 名稱「天然氣表/迴路設定」）

比照水表 `/WaterMeterSetting` 的自參照樹：虛擬節點（不綁 SID）做階層分組，葉子綁實體點位。

| 欄位 | 用途 |
|------|------|
| SID | 葉子綁 Modbus / Calculated / DB 點位；虛擬節點為 NULL |
| UnitScale | 點位原始單位 → m³ 換算係數（m³ / Nm³ / 度 系=1、L 系=0.001）。**綁定時依點位單位定案**，事後改點位單位字串不追溯改義 |
| MaxVolume | 氣表累積讀數溢位上限（**以點位原始單位計**）；讀數倒退且有設 → 套環繞公式，未設 → 該小時 delta=0 並記警告 |
| Sign | 對父節點貢獻方向 ±1（總表 − 已分配子表等算式）；根節點強制 +1 |

### 點位下拉的「單位 + 名稱」雙條件過濾

- **拖曳搬移**：與水表相同 — 可換序 / 跨層搬移，氣表體系**單一根**不能拖出第二個根，跨層 / 放到實體氣表底下先 confirm。規則全文見 [功能說明書_階層樹拖曳搬移.md](功能說明書_階層樹拖曳搬移.md)
判定入口只有一支：`GasMeterCircuitService.ResolveGasPointScale(name, unit)`。點位要同時滿足兩條才會出現在下拉：

**① 單位可換算為 m³**（不分大小寫、常數表 `_unitScaleMap` 可擴充）

| 單位 | 係數 |
|---|---|
| `m³ / m3 / Nm³ / Nm3 / SCM / CMD / CMS / 立方公尺 / 立方米 / 米立方` | 1 |
| **`度` / `氣度` / `天然氣度` / `瓦斯度`** | 1（天然氣帳單 1 度 = 1 m³） |
| `L / liter / litre / 公升 / 升` | 0.001 |

**② 點位名稱含天然氣關鍵字**（`_nameKeywords`，不分大小寫子字串比對）
`天然氣 / 瓦斯 / 燃氣 / 用氣 / 氣量 / 氣表 / 氣度 / 液化石油氣 / 石油氣 / natural gas / nat gas / natgas / gas / lng / cng / lpg`
**或** 單位本身已無歧義（`_unambiguousUnits`：`Nm³ / Nm3 / SCM / 氣度 / 天然氣度 / 瓦斯度`）—
這類單位不可能是電表或水表，故現場命名為「累積量」等泛稱時仍放行，避免真的氣表選不到。

> ⚠️ **為什麼要看名稱**：氣表單位對照表**刻意納入「度」**（與水表刻意排除「度」相反），
> 但「度」同時是 kWh 的俗稱 —— 只看單位會把**電表點位**一起撈進氣表下拉，綁錯就是拿電度數算氣費。
> 單位字串無從分辨電度與氣度，**點位名稱才是現場唯一可靠的訊號**。
> 名稱條件順帶也把同為 m³ / L 的**水表點位**排除在外。
>
> 關鍵字刻意**不收單一個「氣」字**（會誤中空氣 / 氣壓 / 冷氣 / 氣溫），也不收 `NG`（SCADA 慣用 No Good）。

- **下拉找不到氣表點位時**的兩種成因與處置（編輯 Modal「氣量點位」標籤旁 `?` 圖示的 tooltip 內有同樣說明；氣量點位圖示為 `fa-fire`，與樹節點的實體天然氣表一致）：
  ① 點位名稱沒帶關鍵字 → 在點位管理把名稱改成含「天然氣 / 瓦斯 / 用氣量」等字樣；
  ② 單位不是累積氣量單位（例如標成 `Nm³/h` 流量）→ 改標 `Nm³` 或 `m³`。
- 清單顯示「名稱 / 單位 × 係數」（不顯示 SID，搜尋也只比對名稱），單位已無歧義者排前段、靠名稱關鍵字入列者排後。
- **下拉過濾與存檔驗證共用同一支** `ResolveGasPointScale` → 繞過下拉直接 POST 一個電表 SID 也會被擋（回 `invalid_gas_point`）。
- 規則由 `ScadaEngine.Tests/GasMeter/ResolveGasUnitScaleTests.cs` 鎖住，含
  「度在水表回 null、在氣表回 1」的對照斷言、以及「電表點位單位標度但名稱無氣關鍵字 → 一律排除」的核心斷言。
- **UnitScale 由伺服器端定案**：前端傳來的 unitScale 一律不採信，後端依 SID 反查點位單位重算
  （L↔m³ 是 1000 倍差距，前端可竄改會造成無聲的千倍計費錯誤）。
- 刪除節點：有子節點時前端二次確認（`?force=true`），後端遞迴 CTE 一次刪除所有子孫。
  `GasMeterLeafHourly` 以 SID 為 key，迴路刪除後 hourly 列成為孤兒但不再被查詢引用（比照現行做法，可容忍不主動清）。
- 資料表：`GasMeterCircuit`（DatabaseSchema.json 自動建表）。

## 2. Engine 葉子層 hourly 預聚合

`ScadaEngine.Engine/Services/`：

- **GasMeterLeafAggregator** — 純邏輯：單 SID × 單小時取 [hourStart, +1hr) 兩邊界值（HistoryData 最近一筆、staleness window 預設 2h、Quality=1）→ 原始單位相減 + MaxVolume 溢位 → × UnitScale 輸出 m³。
  純邏輯入口 `ComputeFromBoundaries` / `CalcDeltaWithRollover` 為 public static，單元測試（`ScadaEngine.Tests/GasMeter/GasMeterLeafAggregatorTests.cs`）直接鎖規則。
- **GasMeterLeafAggregationService** — BackgroundService：**XX:03** 觸發聚合上一小時 + 啟動 catch-up（預設 24h，缺漏才補）。
  觸發時點刻意錯開：電表 XX:02 / 水表 XX:02 / **氣表 XX:03**，避免三個聚合服務同時掃 `HistoryData` 邊界值。
  斷線恢復不會把累積差灌進單一小時（staleness window 擋掉，恢復首小時記 Q=0 transition）。
- **GasMeterLeafHourlyRepository** — MERGE UPSERT + 從 `GasMeterCircuit` 查葉子清單（SID + MaxVolume + UnitScale）。

Sparse storage 三段語意（同電/水表）：兩邊界有值 → Q=1；只缺一邊 → Q=0、Delta=0（掉線 transition）；兩邊都缺 → 不寫該列。

設定鍵（`ScadaEngine.Engine/appsettings.json`）：`GasMeterAggregation:MaxStalenessHours`（預設 2）、`GasMeterAggregation:CatchUpHours`（預設 24）。

## 3. 用氣報表（/GasUsageReport）

- 粒度：時(日視圖)/日(月視圖)/月(起訖月)/年(起訖年)/**班別**(起訖日)，**月粒度走 `GasBillingPeriods` 氣費期別**（`GasBillingPeriodService`，於 `/GasBillingPeriodSetting` 維護）；**班別粒度**依 `/ShiftSetting` 班別定義分段（每列 = 日期 × 班別 + 非班別補桶，跨日班歸起始日），細節見 docs/功能說明書_班別設定.md。
  ⚠️ **與電費、水費期別皆完全獨立** — 三套抄表日不同，改任一套不影響其他兩套。期別設定改動即時生效、歷史月報自動重算。
  ⚠️ 氣費期別支援**兩月一期**（刪除期別機制）→ 設成兩月一期後，一年月粒度只會產生 **6 個 bucket** 而非 12 個。
- 計算：`GasUsageReportService` **直接加總 `GasMeterLeafHourly`**（per-bucket `SUM(DeltaM3 × EffectiveSign)`）；sign / 階層 / 虛擬節點 on-demand 在 Web 端套，迴路結構改變即時生效不需回填。
- 葉子綁 L（公升）點位時聚合已換算，**報表一律以 m³ 呈現**。
- bucket 內任一葉子有 Q=0 列 → 該 bucket 標 stale（前端 hover 提示資料不完整）。
- 月粒度下方會提示「期別實際區間 + 共 N 期」，兩月一期時期數少於所選月份數，一眼可辨。
- Excel 匯出：`GasUsageReportExcelExporter`（ClosedXML，含子迴路多欄展開，i18n resx）。

## 4. EMS 首頁卡片

三張卡（`EmsCardRegistry` 註冊 order 11/12/13，`/EmsCardSetting` 可顯示/隱藏/排序，預設全部顯示）：

| CardKey | 內容 |
|---------|------|
| `GasUsageBar` | 用氣量長條圖（日/月/年切換；全廠 = 樹根節點） |
| `GasUsagePie` | 根節點直接子迴路用氣占比圓餅圖 |
| `GasCost` | 氣費狀態卡（本期用氣 + 級距明細，見 [功能說明書_氣費設定.md](功能說明書_氣費設定.md)） |

無主氣表概念 — 「全廠用氣」= 樹根節點加總。
JS：`wwwroot/js/ems-hub-gas.js`（一支驅動三卡，各卡以根元素存在防呆）。
API：`GET /EMS/api/gas-circuit-tree` / `gas-usage` / `gas-breakdown` / `gas-cost`。
月檢視（`granularity=day`）取的是**氣費期別**實際起訖日 — `EmsController.ParseGasPivotAsync`；
該月若已被刪除（兩月一期），取「吸收它的那一期」，因此 EMS 月檢視永遠有一段涵蓋該月的期界。

## 6. 已知限制

- **現場需先有天然氣累積量點位**：若 Modbus / DB / OPC UA 尚無此類點位，頁面可先建好但無資料可聚合。
- **不做熱值（kcal/m³）換算**：全系統以 m³（= 1 度）計量，帳單若以熱值計價需另行處理。
- **命名**：氣表統一用 `GasMeter*` 前綴，**不用** `GasCircuit` — 專案已有 `WaterCircuit`（冷凍噸）與 `WaterMeterCircuit`（水表）兩套易混名稱，避免產生第三組。
