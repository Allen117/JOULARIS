# 功能說明書：階層樹拖曳搬移（七個設定頁共用）

> 2026-10-14 新增。本檔是七個「有父子階層」設定頁拖曳行為與防呆規則的**單一真相**；各頁說明書只放一行指引回來。

## 1. 功能概述

七個設定頁的左側樹，都可以用滑鼠把節點拖到別的位置，**同層換順序**或**跨層搬到別的父節點底下**：

| # | 頁面 | 路由 | 資料表 | 根層規則 | 落 DB 時機 |
|---|------|------|--------|----------|-----------|
| 1 | 自來水表設定 | `/WaterMeterSetting` | `WaterMeterCircuit` | **單一根**（全廠），不能拖出第二個根 | 放下即 `PUT api/tree/sort` |
| 2 | 氣表設定 | `/GasMeterSetting` | `GasMeterCircuit` | 同上 | 同上 |
| 3 | 電表迴路設定 | `/EnergyMeter` | `EnergyCircuit` | 允許多根 | 同上 |
| 4 | 空調水系統迴路 | `/ChilledWaterSystem` | `WaterCircuit` | 允許多根 | 同上 |
| 5 | 邏輯流程樹 | `/LogicFlow` | `LogicFlowTree` | 允許多根；**只能放進資料夾** | 放下即 `PUT api/tree/{id}/move` |
| 6 | 圖面設計器頁面樹 | `/Designer` | `ScadaDesignPage` | 允許多根 | **純前端記憶體**，按工具列「儲存」隨整包設計寫回 |
| 7 | 產氣量表設定 | `/AirMeterSetting` | `AirMeterCircuit` | **單一根**（全廠），同氣表 | 放下即 `PUT api/tree/sort` |

水表 / 氣表原本就有「同層拖曳換序」，本次放開跨層；電表 / 空調水 / LogicFlow / Designer 原本完全沒有搬移手段（父節點建立時定死，要改只能刪掉重建）。

迴路資訊四頁（`/ElectricityCircuitInfo` 等）、各報表頁、EMS 卡片、SCADA 監控頁的樹都是**唯讀**，只跟著上面七頁的結果變。

## 2. 操作方式

拖一個節點到目標列上，依滑鼠在目標列的**垂直位置**分三區：

| 位置 | 落點 | 視覺 |
|------|------|------|
| 目標列上 1/4 | 插到目標**之前**（同父） | 目標列上緣藍線 `.drop-before` |
| 目標列下 1/4 | 插到目標**之後**（同父） | 目標列下緣藍線 `.drop-after` |
| 目標列中間 1/2 | **變成目標的子節點**（末位） | 目標列虛線框 `.drop-into` |
| 樹容器空白處 | 搬到**根層末端** | 容器虛線框 `.drop-root` |

不允許的落點在拖曳中就**不會出現任何標記**、放開也不會動（不是放下才報錯）。
中間區若規則不允許變子節點（例如 LogicFlow 的邏輯節點不能有子項），自動退回上半 = before / 下半 = after。

## 3. 防呆規則

### 3.1 共通（前端 `TreeDnd` + 後端 `TreeSortValidator` 雙層）

| 規則 | 前端 | 後端 |
|------|------|------|
| 不能拖到自己身上 | 擋 | 擋 |
| 不能拖到自己的子孫底下（循環） | 拖曳中不顯示落點 | `sort_cycle` |
| 節點 / 目標父節點必須存在 | — | `sort_missing_node` / `sort_missing_parent` |
| 同層且順序沒變 | 不送 API | — |
| 整批寫入交易一致 | — | 任一筆失敗整批 rollback |

後端違規回 **400** `{ success:false, message:<code> }`，前端把 code 翻成 i18n（`{feature}.err.{code}`）。
後端查 DB 現況套上前端送來的 (Id, ParentId, SortOrder) 再驗整棵樹，所以就算前端被繞過、或兩人同時操作，寫進去的仍是合法的樹。

### 3.2 四個迴路頁（1～4）

| 規則 | 水表 / 氣表 | 電表 | 空調水 |
|------|------------|------|--------|
| 根節點可拖？ | ❌（單一根） | ✅ | ✅ |
| 放到根節點前後 / 空白處？ | ❌（會變第二根；後端 `sort_multi_root` 再擋） | ✅ | ✅ |
| 搬到根層時 Sign | — | 後端強制 **+1**（confirm 文案提示「貢獻方向重設為正向」） | 無 Sign 欄位 |
| 跨層搬動 | 放下前 confirm：「搬動後上層迴路的加總與報表會立即改變」 | 同 | 同（文案為冷凍噸） |
| 放到**實體表**（綁 SID）底下 | confirm 多一行警告：該表會連自身一起加總（EMS 說明書 §7.5 已知語意） | 同 | 同（「已綁定點位」） |
| 同層換序 | 直接送，不 confirm | 同 | 同 |

為什麼跨層要 confirm：階層與 Sign 都是 **on-demand 在 Web 端加總**（見 [架構.md](架構.md) §用電報表），放下的瞬間歷史月報、EMS 卡片、Engine 三路虛擬點位全部改用新結構，沒有回填或緩衝。

為什麼水 / 氣鎖單一根：EMS「全廠用水 / 用氣」卡片與迴路資訊頁都取 `TOP 1` 根節點，第二個根會讓全廠數字悄悄變成另一棵樹（見 [功能說明書_用水報表.md](功能說明書_用水報表.md) §4）。

`IsMainMeter`（主要電表）與層級無關，搬動不影響；星號跟著節點走。

### 3.3 LogicFlow（5）

| 規則 | 行為 |
|------|------|
| 只能放進資料夾或根層 | 邏輯節點的「中間區」自動退回 before / after；後端 `move_target_not_folder` |
| 目標資料夾**已停用** | 若被搬子樹內有啟用中的邏輯 → confirm；放下後**後端把整個子樹一併停用**，回 `disabledCount` |
| 搬入收合中的資料夾 | 自動展開 |

為什麼要連動停用：Engine 只看每條 logic 自己的 `IsEnabled`，不看父資料夾（`LogicFlowRepository` 查 `NodeType='logic' AND IsEnabled=1`）。不連動會變成「UI 看起來關了、Engine 還在跑」。

同層同名**不**自動改名（新增 / 改名本來就不檢查重名，複製才有後綴規則），維持一致。

### 3.4 Designer 頁面樹（6）

| 規則 | 行為 |
|------|------|
| 不能拖進自己的子頁 | 拖曳中不顯示落點 |
| 第一個根頁面 = 監控頁預設首頁 | 搬動後若首頁換人，右下 toast 提醒「首頁已變更為 X，按儲存後生效」 |
| 頁面連結元件 | 靠 `PageSid` 指向，搬動不會斷 |
| 畫布 drop | 只認 `widgetType`，頁面拖到畫布不會誤建元件 |
| 未按儲存 | 只在記憶體；離開頁面即遺失（與其他未儲存改動一致） |

## 4. API

| 方法 | 路由 | Body | 說明 |
|------|------|------|------|
| PUT | `/WaterMeterSetting/api/tree/sort` | `[{ id, parentId, sortOrder }, …]` | 受影響兩層（新父層 + 舊父層）整批送回 |
| PUT | `/GasMeterSetting/api/tree/sort` | 同上 | |
| PUT | `/AirMeterSetting/api/tree/sort` | 同上 | 2026-10-15 新增（產氣量表，複製氣表） |
| PUT | `/EnergyMeter/api/tree/sort` | 同上 | 搬到根層的列 `Sign` 強制 1 |
| PUT | `/ChilledWaterSystem/api/tree/sort` | 同上 | |
| PUT | `/LogicFlow/api/tree/{id}/move` | `{ targetParentId, sortOrder }` | 後端自行重排新舊兩層；回 `{ success, disabledCount }` |

五個 sort 端點回應：`200 { success:true }`、`400 { success:false, message:code }`（防呆）、`500 { success:false, message:"sort_failed" }`。
Designer 不打新 API，沿用 `POST /Designer/Save`（`io.js` 展平時以陣列 index 為 `nSortOrder`）。

## 5. 程式結構

| 層 | 檔案 | 角色 |
|----|------|------|
| 前端共用 | `wwwroot/js/common/tree-dnd.js` | `TreeDnd.plan(nodes, dragId, targetId, pos)` 純函式算兩層新順序（含 self / cycle 判定）；`TreeDnd.bind({ container, nodeSelector, idOf, getNodes, canDrop, onDrop })` 事件委派綁一次，樹重繪不用重綁 |
| 前端各頁 | `watermeter.js` / `gasmeter.js` / `energymeter.js` / `chilledwater.js` / `logicflow/tree.js` / `designer/page-tree.js` | 各自 `canDrop`（頁面規則）+ `onDrop`（confirm + 打 API 或改記憶體） |
| 後端共用 | `Services/TreeSortValidator.cs` | `Validate(current, updates, allowMultiRoot)`：存在性 / 循環 / 多根；違規丟 `TreeSortException(code)` |
| 後端各頁 | `EnergyCircuitService` / `WaterCircuitService` / `WaterMeterCircuitService` / `GasMeterCircuitService`.`UpdateSortOrderAsync`、`LogicFlowService.MoveNodeAsync` | 交易內：撈 DB 現況 → Validate → 寫入（根列 Sign=1 / 子樹連動停用） |
| CSS | 各頁 css 的 `.dragging / .drop-before / .drop-after / .drop-into / .drop-root` | 顏色走 `--bs-primary`（EMS 模式自動轉綠）；Designer 深色主題用 `#7ecfff` |

新頁面要接拖曳：載入 `~/js/common/tree-dnd.js`（在頁面主 JS 之前）→ 節點列加 `draggable="true"` + `data-id` → `TreeDnd.bind` → `onDrop` 內 `TreeDnd.plan` 後送 API；後端 Service 在交易內呼叫 `TreeSortValidator.Validate`。

## 7. 驗證方式

離線 Playwright harness（真實 cshtml + wwwroot JS/CSS + 假 fetch，不登入、不碰 DB、不停生產服務）：
以 `page.evaluate` 派發 `DragEvent('dragstart' → 'dragover' → 'drop')`，斷言送出的 PUT body、confirm 文案、以及被擋的案例沒有任何 API 呼叫。
做法與 `.claude/skills/mock-render` 同源；覆蓋案例：單一根三種禁止落點、子孫循環、同層換序不 confirm、跨層 confirm 文案、後端 400 代碼翻 i18n、LogicFlow 退回同層 / 停用資料夾 confirm、Designer 首頁變更 toast / 空白處回根層。

## 8. 已知限制

- 拖曳走 HTML5 Drag and Drop，**觸控裝置**（平板）原生不支援 dragstart；現場若用平板設定，仍需用新增 / 刪除重建。
- 兩人同時拖同一棵樹：後端以 DB 現況驗證不會寫出壞樹，但後送的人會蓋掉先送的人的同層順序；畫面重新載入即可看到最終結果。
- 水 / 氣體系若歷史資料已經是多根（舊版建的），後端 `sort_multi_root` 會擋住任何拖曳，請先手動把多餘的根併回全廠底下。
