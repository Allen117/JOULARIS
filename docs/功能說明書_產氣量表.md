# 功能說明書：產氣量表（空壓機累積式產氣量）

## 1. 功能概述

EMS 設定子頁 `/AirMeterSetting`（EMS 設定 → 產氣量表 → 產氣量表/迴路設定）。
管理**空壓機累積式產氣量**（流量計 totalizer，Nm³ 單調遞增）的迴路階層，唯一用途是作為
[空壓機能源申報](功能說明書_空壓機能源申報.md) 的分母來源（比能耗 kWh/Nm³）。

**刻意不借用氣表（GasMeter*）**：氣表保留給天然氣、綁氣費。若把壓縮空氣點位掛進氣表樹，
氣費會把它當天然氣計價 — 語意錯誤。故平行複製一套 `AirMeter*`，與 `GasMeter*` 互不相干。

本體系**沒有**期別、費率、獨立報表頁；只有迴路樹 + Engine 預聚合 + 一支曆月查詢。

## 2. 資料流

```
產氣量點位（Modbus / Calculated / DB，累積讀數 Nm³ / m³ / SCM / NL）
    ↓ HistoryData（與電/水/氣表同管線）
Engine AirMeterLeafAggregationService（XX:04 觸發 + 啟動 catch-up AirMeterAggregation:CatchUpHours，預設 24）
    │  AirMeterLeafAggregator：每葉子 SID 取 [hourStart, +1hr) 兩邊界值（staleness window
    │  AirMeterAggregation:MaxStalenessHours 預設 2）→ 原始單位相減 + MaxVolume 溢位 → × UnitScale 換算 Nm³
    ↓ UPSERT (MERGE on (SID, HourStart))
AirMeterLeafHourly (SID, HourStart, DeltaNm3, Quality, IsRolledOver, CreatedAt)
    ↓ Web AirMeterUsageReportService.GetCalendarMonthlyReportAsync(circuitId, year)
      per-bucket SUM(DeltaNm3 × EffectiveSign)（sign / 階層 / 虛擬節點 on-demand）
空壓機能源申報（/AirCompressorDeclaration）
```

演算法與 `GasMeterLeafAggregator` **完全對稱**（sparse storage 三段語意：兩邊界都缺不寫列 / 缺一邊 Q=0 Delta=0 / 兩邊都有 Q=1；
MaxVolume 溢位環繞；UnitScale 換算），兩套各自獨立 — 改產氣量邏輯不可能弄壞氣費。

觸發時點錯開：電表 XX:02 / 水表 XX:02 / 氣表 XX:03 / **產氣量表 XX:04**。

## 3. 點位判定（單位 + 名稱，三條件）

唯一入口 `AirMeterCircuitService.ResolveAirPointScale(name, unit)`，下拉過濾（`GET /AirMeterSetting/api/sids`）
與存檔驗證（POST / PUT 由伺服器依 SID 重新定案 UnitScale，不採信前端）共用同一支：

1. **單位可換算 Nm³**：`Nm³ / Nm3 / m³ / m3 / SCM / 立方公尺 / 立方米` → 1；`L / NL / liter / litre / 公升` → 0.001
2. **且** 點位名稱含空壓關鍵字：`空壓 / 壓縮空氣 / 產氣 / 氣量 / air / compressor / FAD`（不分大小寫、子字串比對）
3. **且** 名稱**不含**天然氣字樣：`天然氣 / 瓦斯 / 燃氣 / 石油氣 / natural gas / nat gas / natgas / LNG / CNG / LPG`

與氣表的刻意差異：

| 項目 | 氣表 GasMeter | 產氣量表 AirMeter | 理由 |
|---|---|---|---|
| 單位「度」 | 收（天然氣 1 度 = 1 m³） | **不收** | 空壓無此慣例；「度」是 kWh 俗稱 |
| 單位無歧義免名稱 | Nm³ / SCM 免名稱關鍵字 | **無此捷徑** | Nm³ 對天然氣與壓縮空氣都成立 |
| 名稱排除表 | 無 | 有（天然氣字樣） | 空壓關鍵字「氣量」會命中「天然氣氣量」 |

- 刻意不收單一個「氣」字（誤中天然氣 / 氣壓 / 冷氣 / 氣溫）
- 流量單位（`Nm³/min`、`Nm³/h`）一律排除 — 只收累積量；現場流量計請綁 totalizer 點位
- m³ 視同 Nm³：系統不做溫壓修正，假設流量計累積值已換算為標準狀態
- 規則由 `ScadaEngine.Tests/AirMeter/ResolveAirUnitScaleTests.cs` 鎖住（含「天然氣點位在產氣量表回 null」、「度」在氣表/產氣量表回不同值）

## 4. 頁面操作

版面、操作與氣表/迴路設定頁完全相同：

1. 左側樹：新增根節點（全廠，只允許一個根）→ 底下新增子節點
2. 節點類型：**虛擬迴路**（不綁點位，加總子節點，例如「空壓機房總產氣 = 1 號 + 2 號 + 3 號」）或**實體產氣量表**（綁一個產氣量點位）
3. 貢獻方向 ±1：建立「總表 − 已分配子表」算式；根節點固定 +
4. 實體表可設溢位上限 MaxVolume（以點位原始單位計），totalizer 歸零時用於計算 delta；留空 = 倒退時該段視為 0
5. 拖曳搬移：共用 `TreeDnd` + 後端 `TreeSortValidator`（循環 / 單一根 / 節點存在三重防呆）→ [功能說明書_階層樹拖曳搬移.md](功能說明書_階層樹拖曳搬移.md)

## 5. 路由

| Method | Route | 說明 |

## 7. 資料表

`AirMeterCircuit`：Id / Name / ParentId / SortOrder / SID / UnitScale / MaxVolume / Sign / Description / CreatedAt / UpdatedAt（結構同 `GasMeterCircuit`）。

`AirMeterLeafHourly`：SID + HourStart（PK）/ DeltaNm3 / Quality / IsRolledOver / CreatedAt（結構同 `GasMeterLeafHourly`，增量欄名為 `DeltaNm3`）。

皆由 `DatabaseSchema.json` 啟動自動建表。

## 8. 設定（Engine appsettings.json）

```json
"AirMeterAggregation": {
  "MaxStalenessHours": 2,
  "CatchUpHours": 24
}
```

## 9. 權限 / i18n

- `PermissionService.ConfigurablePages` + `EmsRoutes` 加 `/AirMeterSetting`（帳號管理可單獨配置、套 EMS 綠色主題）
- Layout：EMS 設定 → 產氣量表 → 產氣量表/迴路設定（`layout.menu.group_air_meter` / `layout.menu.air_meter`，icon `fa-wind`）
- 全站搜尋（Ctrl+K）已收錄

## 10. 已知限制

- 無獨立產氣報表頁，數字只在空壓機能源申報頁呈現（曆月粒度）
- 預聚合延遲：最近一小時在 XX:04 之前尚未聚合，當月（進行中）數字可能偏低
- 不做溫壓修正、不做比功率 kW/(Nm³/min)（使用者決策：只用比能耗）
