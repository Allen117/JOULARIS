# 功能說明書：契約容量最佳化

> 路由 `/ContractCapacity`（EMS「報表查詢」選單）· 2026-10 新增

## 功能總覽

用歷史需量回測「經常契約容量訂多少最省」：

- **保守建議**：回測期每個月都不超約的最小經常契約（進位至取整單位，預設 10 kW）
- **最低成本點**：回測期需量費用（基本電費 + 超約附加費）最低的經常契約，通常會容許部分月份超約
- **平底區間**：與最低成本差 ≤ 1% 的經常契約範圍 — 成本曲線底部通常很平，讓使用者在風險與省錢之間自行權衡
- 三方案（現行 / 保守 / 最低成本）逐月對照 + 回推節省金額 + 匯出 Excel

> ⚠️ 節省金額是「若回測期間即採用該契約容量」的**回推值**，不是未來保證。頁面與 Excel 都保留此聲明。

## 第一性原理

```
每月需量費 = 契約容量 × 單價 + 超約附加費

Cost_m(C) = C·p_m + 2p_m·min(max(D_m − C, 0), 0.1C) + 3p_m·max(D_m − 1.1C, 0)
最佳契約 C* = argmin Σ_m Cost_m(C)
節省金額    = Σ Cost_m(現行契約) − Σ Cost_m(C*)
```

契約訂高，每個月都多付基本電費；訂低，超約月份付 2～3 倍罰金。

## 資料流

```
電費設定（SystemSettings.electricity_tariff）
  ├─ adoptions / plans → 每計費月的電價方案（取期別起日有效者）→ 各契約別單價、夏月區間、時段表
  └─ contracts         → 每計費月的現行契約 kW（取期別起日有效者）
DemandData（Engine 每分鐘 ΔkWh×4）
  └─ 只取 Timestamp 分鐘 ∈ {0,15,30,45} 的樣本 = 台電固定 15 分鐘窗口
          ↓ ContractCapacityService（Web，on-demand，不建聚合表）
     每計費月：尖峰時間最高需量 + 窗口完整率 + 夏月日數占比
          ↓ ContractCapacityCalculator（Common 純函式，單元測試鎖住）
     現行 / 保守 / 最低成本 / 平底區間 / 成本曲線 / 逐月明細
```

- **計費月 = 電費期別**（`BillingPeriods`，未自訂時為曆月），與電費報表一致
- 一年單一迴路約 3.5 萬筆整刻樣本，即時查詢負擔小，因此不另建 `DemandMonthly` 預聚合表

## 台電規則（查證出處）

出處：台灣電力公司「電價表」（中華民國 114 年 11 月 17 日經濟部經授能字第 11400334600 號函同意備查），2026-10-16 自台電官網下載查證。

| 規則 | 原文要點 | 電價表位置 |
|---|---|---|
| 超約附加費 | 當月用電最高需量超出契約容量時，在契約容量 10% 以下部分按 2 倍、超過 10% 部分按 3 倍計收基本電費，不給予功率因數扣減及基本電費折扣 | 第四章（低壓電力）七、第五章（高壓及特高壓）七 |
| 二段式尖峰超約門檻 | 夏月尖峰時間超約瓩數 = 尖峰最高需量 − 經常契約；**非夏月** = 尖峰最高需量 − (經常 + 非夏月契約) | 同上 |
| 三段式尖峰超約門檻 | 尖峰時間超約瓩數 = 尖峰最高需量 − 經常契約 | 同上 |
| 電動車充換電設施 | 超約瓩數 = 當月最高需量（全時段）− 經常契約 | 同上 |
| 週六半尖峰 / 離峰契約基本費 | 單價 × [(週六半尖峰 + 離峰) − (經常 + 非夏月或半尖峰) × 0.5]，負值按 0 | 第三～五章 五、電費之計算 |
| 非夏月契約 | 只在非夏月計費，於非夏月尖峰時間併同經常契約使用 | 第八章 二、需量契約容量 |
| 需量定義 | 以雙方約定最高需量（15 分鐘平均）為契約容量 | 第八章 二 |
| 高壓 / 特高壓夏月 | 5 月 16 日至 10 月 15 日 | 第五章 四、電價 |
| 高壓以上最低契約 | 二段式 / 三段式各契約別合計不低於 100 瓩 | 第八章 二 (二) |

**電價表內查無、未逐條驗證的項目**（頁面與 Excel 已註明，實際申請前請向台電確認）：

- 抄表期跨夏月與非夏月時基本電費如何分計 — 本系統以**夏月日數比例加權**兩季費用（與電費計算的既有慣例一致）
- 契約容量調整限制（多久能調一次、下調條件）— 屬台電營業規章範圍，電價表未載；本版不做限制檢查

## 計算細節

### 每月最高需量（固定窗口）

- `DemandData` 每分鐘以 ΔkWh×4 算「過去 15 分鐘」，因此 `Timestamp = t`（分鐘 ∈ {0,15,30,45}）代表窗口 `[t−15, t)`
- 計費月 `[起, 訖)` 內的窗口 = `t ∈ (起, 訖]`（起點 00:00 那筆屬上一期的最後一窗）
- 有效樣本：`Quality = 1` 且需量 ≥ 0；**異常值上限**（選填，例如填變壓器容量）以上視為電表跳動，計入「排除」、不算有效
- **尖峰篩選**：tou 方案依窗口起點落在時段表的 `peak` 才列入最高需量（季節 / 日別 / 假日判定同電費計算 `ResolvePeriodAt`）；非時間電價與電動車方案（`*_ev`）取全時段

### 窗口完整率

`有效窗口數 ÷ 應有窗口數`；進行中的計費月只算到現在（往下取整刻）。低於門檻（預設 95%）的月份標「不可評估」，**不列入任何合計與建議**，KPI 顯示可評估月數。

不可評估原因：`no_plan`（該期未採用電價方案）/ `no_demand_tariff`（方案無經常契約，如表燈累進）/ `low_completeness` / `no_data`（無尖峰需量）。

### 單月費用（`ContractCapacityCalculator.MonthCost`）

兩季各算一次，以夏月日數占比 `s` 加權：`Cost = s·Cost_夏 + (1−s)·Cost_非夏`

```
經常契約基本費 = C × 經常契約單價(季)
其他契約別基本費 = [非夏月契約 × 單價（僅非夏月）]
               + 半尖峰契約 × 單價(季)
               + 週六半尖峰/離峰單價(季) × max(週六半尖峰 + 離峰 − (C + 非夏月 + 半尖峰) × 0.5, 0)
門檻 T = C（夏月）／ C + 非夏月契約（非夏月）
超約 = max(D − T, 0)
附加費 = 經常契約單價(季) × [2 × min(超約, 0.1T) + 3 × max(D − 1.1T, 0)]
```

- 只計入**採用方案 `baseFees` 有的契約別**（契約紀錄多填的 key 不計費）
- 週六半尖峰 / 離峰扣抵項會隨經常契約變動，因此即使只搜尋經常契約，該項也逐 C 重算

### 建議值

- **保守**：`max_m(全夏月 ? D_m : D_m − 非夏月契約)` 無條件進位至取整單位
- **最低成本**：以 1 kW 步距在 `[1, ceil(回測期最高需量) + 1]` 全域搜尋（同成本取較小值）；高於最高需量後不再有超約、費用隨 C 單調增加，上界足夠
- **現行**：逐月套用當月有效契約；回測期間有任一可評估月份查無契約紀錄 → 現行與節省金額顯示「未設定」

## 範例（設計預覽情境，單元測試鎖住）

高壓二段式，單價 223.6 / 166.9，現行經常契約 1,500 kW，12 個月最高需量 968～1,396 kW：

| 方案 | 經常契約 | 年需量費 | 節省 |
|---|---|---|---|
| 現行 | 1,500 kW | 3,429,450 | — |
| 保守 | 1,400 kW | 3,200,820 | 228,630（6.7%） |
| 最低成本 | 1,236 kW | 3,034,888 | 394,562（11.5%，4 個月超約） |

平底區間 1,194～1,310 kW。跨季月份加權單價：2025-10 → 194.3、2026-05 → 196.2。

## 畫面

1. **回測條件**：計費迴路（`EnergyCircuit.IsDemandEnabled = 1` 且綁 SID，主要電表排最前標 ★）、回測起訖（`yyyy-MM`，預設上個月往回 12 個月，上限 24 個月）、保守取整（1/5/10/50/100 kW）、窗口完整率門檻、異常值上限
2. **KPI 四卡**：現行需量費 / 保守建議 / 最低成本點 / 資料品質
3. **成本曲線**：堆疊面積（基本電費 + 超約附加費）× 經常契約，標出三條垂直線與平底區間
4. **逐月最高需量 vs 契約線**：柱狀（夏月深色、不可評估灰色）+ 現行（階梯，契約變更時會跳）/ 保守 / 最低成本三條線
5. **逐月明細**：單價、最高需量、發生窗口、完整率（含排除筆數）、三方案超約 kW 與費用；合計與節省

## 已知限制 / 後續版本

- **只最佳化經常契約**；半尖峰、週六半尖峰、離峰契約依現行值固定計入，**這些時段的超約不計入**（多契約別聯合最佳化列第二階段，需逐條對照「超出部分不重複計算」規則）
- 每計費月的方案與契約取**期別起日**有效者；期中變更不按日拆分
- 三段式「尖峰時間可變動」方案的台電指定 30 日未建模，尖峰窗口依時段表判定
- 未檢查台電契約調整限制與最低契約容量（高壓以上 100 瓩）
- `DemandData` 由 kWh 差值推得，電表跳動 / 重置可能產生假尖峰：`Quality = 0` 與負值已排除，其餘請以「異常值上限」過濾，並對照明細的「發生窗口」人工確認
- 功率因數調整、營業稅等不在需量費範圍內，未計入
