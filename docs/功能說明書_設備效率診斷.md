# 功能說明書：設備效率診斷（冰機 / 空壓機）

## 1. 功能概述

冰機與空壓機各一個診斷頁，邏輯完全相同，只差「角色清單 / 指標公式 / 門檻」三張表：

| 頁面 | 路由 | 用途 |
|---|---|---|
| 設備效率設定 | `/EquipmentEfficiencySetting?kind=chiller\|compressor` | 冰機 / 空壓機兩 tab：掃描點位自動判定設備、手動新增、編輯角色點位與門檻、回填歷史 |
| 冰機效率診斷 | `/ChillerEfficiency` | 即時 kW/RT 卡 + 期間儀表板 |
| 空壓機效率診斷 | `/CompressorEfficiency` | 即時比功率卡 + 期間儀表板；另有「系統診斷」/「診斷設定」tab（空壓系統規則式診斷，見 §12） |
| EMS 首頁卡片 | `/EMS` 的 `ChillerEfficiency` / `CompressorEfficiency` | 每類一張設備列表卡（可在 `/EmsCardSetting` 隱藏 / 排序） |

**第一性原理**：效率 = 產出 ÷ 投入。整個功能只有三件事：

1. **設備 → 角色點位的綁定**（`EquipmentProfile` + `EquipmentPointBinding`）
2. **瞬時值**：各角色點位現值代入純函式 → 即時卡
3. **逐時累計**：Engine 每小時把每台設備的 ΣkWh 與 Σ產出寫進 `EquipmentHourly`；期間效率 = ΣkWh ÷ Σ產出（**能量加權**，不是逐時效率的平均）

> ⚠️ **與其他體系無關**：本功能的設備主檔與空調水系統迴路（`WaterCircuit`，冷凍噸）、自來水表、氣表、產氣量表（`AirMeter*`，空壓機能源申報用的累積式 Nm³）都**沒有**關聯。冰機的 RT 點位可同時被 `WaterCircuit` 葉子引用；空壓機這裡吃的是**瞬時空氣量 m³/min**，不是產氣量表的累積讀數。

## 2. 指標與標準出處

### 2.1 冰機 — ASHRAE 90.1 / AHRI 550/590

| 指標 | 公式 | 備註 |
|---|---|---|
| **kW/RT**（主指標） | kW ÷ RT | 越低越好 |
| COP | 3.517 ÷ (kW/RT) | 1 RT = 3.517 kW 冷量 |
| EER | 12 ÷ (kW/RT) | Btu/h per W |
| 負載率 | LOAD 點；否則 RT ÷ 額定 RT | % |
| 冰水 ΔT | CHWR − CHWS | |
| 冷卻水 ΔT | CDWR − CDWS | |
| 蒸發器趨近 | CHWS − 蒸發飽和溫度 | 有綁 EVAPT 才顯示 |
| 冷凝器趨近 | 冷凝飽和溫度 − CDWR | 有綁 CONDT 才顯示 |

**冷量來源**：主路徑 = 冰水流量 + 進出水溫計算；有直接 RT 點者為備選。

```
RT = (L/min ÷ 60) × ΔT × 比熱 ÷ 3.517      （水密度取 1 kg/L，比熱預設 4.186 kJ/(kg·K)）
例：1,000 L/min、ΔT 5 °C → 99.18 RT      （ΔT 1 °C → 19.84 RT）
```

- 流量 ≤ 0 或 ΔT ≤ 0 → 冷量 0（泵停 / 停機時的溫差雜訊不算冷量）；任一值缺 → 無法計算
- 乙二醇系統比熱不同 → 設定頁「比熱」欄調整（`EquipmentProfile.SpecificHeat`）
- 兩者皆綁時以計算值為準，RT 點只在即時卡顯示「RT 點對照」

### 2.2 空壓機 — ISO 11011 / CAGI（ASHRAE 不涵蓋壓縮空氣系統）

| 指標 | 公式 |
|---|---|
| **比功率 kW/(m³/min)**（主指標） | kW ÷ 空氣量 |
| kW/100cfm | 比功率 × 2.8317（100 cfm = 2.8317 m³/min） |
| 比能耗 kWh/m³（僅期間） | ΣkWh ÷ Σm³ |
| 負載率 | LOAD 點；期間若有 LOADED 點 → 加載時數 ÷ 運轉時數；否則 kW ÷ 額定 kW |

### 2.3 評級與停機

- 主指標 **≤ Good → 優**、**≤ Fair → 可**、**> Fair → 差**（等於門檻歸較好級）
- 預設門檻：冰機 0.65 / 0.85 kW/RT（水冷離心機 ASHRAE 90.1 滿載區間附近，風冷機應上調）；空壓機 7 / 9 kW/(m³/min)（CAGI 螺旋式常見區間）。**預設值僅供起點**，請依銘牌 / 驗收報告調整
- 停機：有 RUN 點 → RUN < 0.5；否則 kW ≤ 額定 kW × 5%（未填額定 → 1 kW）。停機 → 評級「停機」、效率不計算
- 無即時值 / 品質非 Good / 運轉中但產出為 0（無法相除）→「資料不足」，不顯示 0

### 2.4 期間（累計）

- 期間效率 = Σ kWh ÷ Σ 產出（AHRI 550/590 IPLV 與 ASHRAE Guideline 22 的能量加權精神）
- 負載率分佈：運轉小時依平均負載率分 ≤25 / 25–50 / 50–75 / >75% 四段（對應 IPLV 四個負載點），顯示各段的 kWh 占比、產出占比與該段效率
- 期間切界 = **曆制**（日 / 曆月 / 曆年），刻意不走任何月結期別 — 與 `/ChilledWaterCircuitInfo` 同語意（`EmsController.ParseCalendarPivot`）

公式全部集中在 Common `EquipmentMetricCalculator`（純函式），Engine 聚合與 Web 即時 / 期間共用同一組，避免「現在 0.62 但本小時平均 0.70」因公式不同被當 bug。

## 3. 角色與單位

角色鍵 = Common `EquipmentRoles` 常數（唯一真相），存進 `EquipmentPointBinding.Role`；前端 `role-aliases.js` 的 `_equipRoleAliases` 用同一組字串。

| 角色 | 冰機 | 空壓機 | 基準單位 | 可選單位 |
|---|---|---|---|---|
| KW | 必要* | 必要* | kW | kW / W / MW |
| KWH | 必要* | 必要* | kWh | kWh / Wh / MWh（累積點，邊界相減 + MaxKwh 溢位） |
| FLOW | **產出主路徑** | — | L/min | L/min / L/s / m³/h / GPM |
| CHWS / CHWR | 產出主路徑 | — | °C | °C |
| RT | 產出備選 | — | RT | RT / USRT / kW（冷量） |
| CDWS / CDWR / EVAPT / CONDT | 輔助 | — | °C | °C |
| AIRFLOW | — | **必要** | m³/min | m³/min / m³/h / Nm³/h / cfm / L/min |
| DISCHPRESS | — | 輔助 | bar | bar / kPa / psi / MPa |
| DISCHTEMP | — | 輔助 | °C | °C |
| LOADED | — | 輔助 | 狀態 | ≥ 0.5 = 加載 |
| LOAD | 輔助 | 輔助 | % | % |
| RUN | 輔助 | 輔助 | 狀態 | ≥ 0.5 = 運轉 |

\* KW 與 KWH 擇一必要；兩者皆有時 kWh 以 KWH 為準、即時 kW 用 KW。冰機產出必要 = FLOW + CHWS + CHWR 三者齊，或 RT。

- **單位換算**：綁定時存 `Scale`（原始值 × Scale = 基準單位），由伺服端依單位重算（`EquipmentUnitScale`），前端不能指定係數。溫度只收 °C（°F 需偏移量，請先以計算點位轉換）
- 掃描時依點位 `Unit` 欄猜單位（`LPM` → L/min、`CMH` → m³/h、`Nm3/h` → Nm³/h …，別名表由 `/EquipmentEfficiencySetting/api/meta` 下發）；認不得 → 基準單位，使用者在下拉改

## 4. 設定頁：掃描 / 手動 / 編輯

### 4.1 掃描判定（`js/equipment-scan.js`，純函式）

1. 點位清單 = `PointPicker.load()`（`/Designer/Points` + `/Designer/Devices`，每點算好 `szDeviceLabel`）
2. 依 `szDeviceLabel` 分群 — 設備邊界 = 既有 Device 分群（Tag.Device → 多站號子設備 → Coordinator 名 / DB 群組 / 計算群組 / OPC UA DeviceName）
3. 每群以 `_equipRoleMatch.resolveEquipRole(name, 該 kind 的角色)` 比對（整名 → 尾 token → 字尾式）；落空時再試**中文別名包含式**（名稱含 ≥ 3 字的中文別名即命中、最長優先 → 吃「冰水出水溫度」「冷卻水進水溫度」；2 字別名如「功率」不走包含式，避免「功率因數」被當 KW）
4. 冰機群另吃 `WaterCircuit` 葉子已綁的 RT 點（名稱不像 RT 也會被認成 RT 角色）
5. 判定：冰機特徵角色 FLOW / CHWS / CHWR / CDWS / CDWR / RT / EVAPT / CONDT；空壓機特徵角色 AIRFLOW / DISCHPRESS / DISCHTEMP / LOADED；群名含「冰機 / 主機 / chiller / CH#」或「空壓 / air comp / compressor / AC#」+2 分。**本 kind 分數 > 0 且 ≥ 另一 kind** 才列為候選（同一群不會同時被兩邊搶，平手兩邊都列）
6. 信心：必要角色齊 + 特徵 ≥ 2 或群名命中 → 高；齊 → 中；不齊 → 低

### 4.2 帶入規則

- 進入某 tab 時該類 **0 台** → 自動掃描，有新候選就彈「掃描到 N 台疑似{冰機|空壓機}，要帶入嗎？」；也可隨時按「重新掃描」
- 每台列出設備名（可改）、判定依據（命中哪些角色）、各角色命中點位（下拉列群內點位，「…」可從其他設備挑）、單位、多筆命中標「N 筆命中」（取第一筆）
- **已存在**（同名，不分大小寫；或任一主要 SID — KW / KWH / FLOW / RT / AIRFLOW — 相同）→ 標「已存在」、預設不勾
- **缺必要點位的候選不能勾選**，需先在面板內補齊（「必要角色未綁不可存」由伺服端驗證保證）
- 帶入 = `POST api/profiles/batch`，同一交易寫入；任一台驗證失敗整批不寫。門檻帶預設值

### 4.3 手動新增 / 編輯

名稱、排序、啟用、額定產出（冰機 RT / 空壓機 m³/min）、額定 kW、KWH 溢位上限、門檻（優 / 可）、比熱（冰機）、備註；各角色以共用 PointPicker（來源 → 設備 → 點位）綁定 + 單位下拉。缺必要角色時「儲存」停用並提示缺什麼。設備種類不能經編輯改變（冰機改空壓機 = 綁定全錯，請刪除重建）。刪除連同綁定與 `EquipmentHourly` 列一併刪除。

### 4.4 生效時機與回填

- 存檔後 **Engine 免重啟**：聚合服務每次觸發都重讀設定，下一個整點（XX:06）起依新設定聚合
- 改了綁定 / 單位要補算過去的資料 → 「回填歷史」（單台或全部，最多 366 天）→ `POST api/backfill` → MQTT `SCADA/Sys/EquipmentHourly/Backfill` → Engine 逐小時重算覆寫（`IsBackfilled=1`），重算後判定資料不足的小時舊列一併刪除

## 5. 資料表（`DatabaseSchema.json`，啟動自建）

| Table | Key | 用途 |
|---|---|---|
| `EquipmentProfile` | Id (PK), Kind, Name, SortOrder, IsEnabled, RatedOutput, RatedPower, MaxKwh, SpecificHeat, GoodThreshold, FairThreshold, ControlType, MinLoadPct, MaxPressure, MaxStartsPerHour | 設備主檔（後四欄僅空壓機、皆可 NULL，空壓系統診斷用；冰機存檔一律清空） |
| `EquipmentPointBinding` | ProfileId + Role (PK), SID, Unit, Scale | 角色點位綁定（應用層維護參照，無 DB FK） |
| `EquipmentHourly` | ProfileId + HourStart (PK), Kwh, OutputQty, RunHours, AvgLoadPct, LoadedHours, AvgPressure, SampleCount, Quality, IsBackfilled | 設備層 hourly 預聚合 |
| `CompressorDiagnosisSetting` | Id=1 (PK), SettingJson, UpdatedAt, UpdatedBy | 空壓系統診斷場域設定（§12.4） |
| `CompressorDiagnosisSnapshot` | Id (PK), RunAt, PeriodFrom, PeriodTo, IsScheduled, ResultJson, RunBy | 空壓系統診斷結果快照（§12.5） |

`EquipmentHourly.Quality` 語意：

| 情況 | 寫入 |
|---|---|
| kWh 與產出皆足量 | Quality=1，計入期間效率分子分母與覆蓋率 |
| kWh 足量、產出樣本不足（流量計 / 溫度計斷線）且有運轉 | Quality=0、OutputQty=NULL；期間效率不計、覆蓋率算缺漏 |
| 整小時停機且產出點缺值 | Quality=1、OutputQty=0（無可量測，避免停機時段誤觸覆蓋率警示） |
| kWh 無法求得 | 不寫列（sparse，同 `WaterLeafHourly`） |

## 6. Engine 聚合（XX:06）

```
EquipmentProfile + EquipmentPointBinding（每次觸發重讀，設定免重啟）
    ↓ EquipmentHourlyAggregationService（XX:06 + 啟動 catch-up 24h；設定區段 EquipmentAggregation）
    ↓ EquipmentHourlyAggregator.ComputeAsync
        ① 一條 SQL 取該設備所有瞬時角色 SID 在該小時的「分鐘平均」樣本
           SELECT SID, DATEDIFF(MINUTE, @t0, Timestamp) AS M, AVG(Value) … GROUP BY SID, M
        ② 有 KWH 點 → 兩端邊界值（staleness window）相減 + MaxKwh 溢位（同 EnergyLeafAggregator）
        ③ ComputeFromSamples（純函式，單元測試鎖住）：
           kWh   ：KWH 邊界相減優先；KWH 未綁或缺邊界 → AVG(kW) × 1h
           冷量  ：FLOW + CHWS + CHWR **分鐘對齊**（三者同一分鐘都有值才算）逐分鐘算 RT 再 AVG × 1h
                   — 變流量系統不可用 AVG(flow) × AVG(ΔT)（測試案例：兩者差 35.7 vs 59.5 RT·h）
                   否則 RT 點 AVG × 1h
           空氣量：AVG(m³/min) × 60 → m³
           運轉  ：RUN 點樣本占比；無 RUN → kW > 額定 × 5% 占比；只有 KWH → 本小時 kWh > 門檻即 1
           負載率：運轉中分鐘的 LOAD 平均；否則冰機 = 運轉期間平均 RT ÷ 額定、空壓機 = 加載 ÷ 運轉、再否則 kWh ÷ 運轉 ÷ 額定 kW
           空壓機另算加載時數、運轉期間平均排氣壓力
EquipmentHourly
```

觸發分鐘錯開：電 / 冷凍噸 / 自來水 XX:02、氣 XX:03、產氣量表 XX:04、Web 電費 XX:05、**設備效率 XX:06**。

`appsettings.json` → `EquipmentAggregation`：

| 鍵 | 預設 | 意義 |
|---|---|---|
| `MinSamplesPerHour` | 30 | 產出 / kW 樣本分鐘數門檻，低於視為資料不足 |
| `MaxStalenessHours` | 2 | KWH 邊界值回溯上限 |
| `CatchUpHours` | 24 | 啟動補算範圍 |
| `BackfillBatchSleepMs` | 500 | 回填每月一批後休息 |

Web 端可選 `EquipmentEfficiency:MinCoveragePercent`（預設 90）調整覆蓋率警示門檻。

## 8. 診斷頁與卡片

- **即時**（30 秒輪詢）：每台一張小卡 — 運轉燈、主指標大字 + 評級色、COP / kW/100cfm、kW、產出、輔助指標、最後更新時間、門檻
- **累計**：日（逐時）/ 月（逐日）/ 年（逐月）+ pivot；tiles（期間平均效率含 COP·EER 或 kW/100cfm·比能耗、總耗電、總產出、運轉時數、平均負載率；空壓機另有加載時間比、平均排氣壓力）、效率趨勢（每台一條 + 全場加權虛線）、負載率分佈、設備排名（依期間效率由低到高，無值排最後；評級依各台門檻）、覆蓋率警示（未來時數不計入分母、報最差那台）
- 0 台設備 → 顯示引導至設定頁
- **EMS 卡片**：每台一列（運轉燈 / 名稱 / 即時主指標 / 評級）+ 底部「本曆月累計平均效率・運轉時數」；標題連到診斷頁；0 台 → 「尚未設定」+ 設定頁連結
- 兩個診斷頁共用 `Views/Shared/_EquipmentDiagnosis.cshtml` + `js/ems-equipment.js`（讀 `data-kind`），只差標題；兩張卡共用 `js/ems-hub-equipment.js`

## 9. 權限、主題、i18n

- 三頁皆列入 `PermissionService.ConfigurablePages`（逐頁可勾）與 `EmsRoutes`（EMS 綠主題）。EMS 選單新增「設備效率」dropdown（冰機 / 空壓機效率診斷）排在「迴路資訊」之後；「能管設定」加「設備效率 → 設備效率設定」
- `/EMS/api/equipment/*`：有該 kind 診斷頁或 `/EMS` 權限即可讀（EMS 卡片在首頁顯示）
- zh-TW / en 雙語：
  - JS 字串（`eq.*`）集中在 `Resources/EquipmentEfficiency.{,en}.resx`（無對應 C# 類別，供 `/api/i18n` 字典合併，同 `ScadaAssistant.resx`）— 設定頁、兩個診斷頁、兩張卡共用
  - Razor 字串：設定頁 `Features.EquipmentEfficiencySetting.Views.Index`、共用版面 `Views.Shared._EquipmentDiagnosis`、兩頁標題各自的 `Features.{Chiller,Compressor}Efficiency.Views.Index`、卡片 `Features.Ems.Views._Card{Chiller,Compressor}Efficiency`、卡片名稱 `emscard.name.chillerefficiency / compressorefficiency`

## 11. 已知限制

- **Device 欄空白的站**：分群退到 Coordinator 整站，同角色多筆命中機率高 → 掃描面板標「N 筆命中」由使用者挑；補 Device 欄才是正解
- **即時快取只有 MQTT 到過的點**：Web 剛啟動時即時卡顯示「資料不足」而非 0
- **分鐘對齊依賴 HistoryData 分鐘級 dedup**：輪詢週期長於 1 分鐘的來源（部分 DB 來源）每小時樣本可能 < 30 → 該小時不寫列；可調 `MinSamplesPerHour`
- 溫度只支援 °C；°F 現場請先建計算點位轉換
- 不內建 ASHRAE 90.1 Table 6.8.1 最低效率表（依機型 × 噸數分級、每版不同），門檻由使用者填

## 12. 空壓系統規則式診斷（`/CompressorEfficiency`「系統診斷」/「診斷設定」tab）

把 `compressor-analysis-skill`（d400-air-compressor）的空壓系統標準分析流程套到本系統：**只移植領域知識層**（指標、資料品質特徵、四個機會的判斷路徑、經濟換算），**不移植 LLM 工作流層**（訪談、checkpoint、跨對話記憶、報告撰寫）。LLM 原本負責的「判斷」改由確定性規則 + 設定頁的場域事實取代；「寫報告」改由 i18n 文案模板代入數字。**同輸入必同輸出，不呼叫任何 LLM / 外部服務。**

結論只到「篩檢 + 建議下一步（試驗 / 量測 / 維修 / 不需動作）」，所有節能皆為**篩檢估計區間**，不宣稱已驗證節能（與原 skill「需量測回應或試驗才能報 supported savings」一致）。

### 12.1 規則

| ID | skill 對應（優先序） | 觸發條件 | 篩檢節能 | 建議下一步 |
|---|---|---|---|---|
| D | trusted-data（前置） | 任一已綁點位：覆蓋率 < 門檻、平線（非零值長時間不變）、哨兵值 / 負值、RUN / LOADED 與 kW 矛盾、長缺口 | — | 修正資料 |
| P | ① pressure-optimization | 運轉期間供氣 P50 > 需求壓力 × 裕度（1.10），且可降量 ≥ 一個試驗步階 | 可降 bar × 5%~6% × 期間 kWh | 有末端壓力 → 降壓試驗；無 → 先量測末端壓力 |
| L | ② leakage-and-idle-loss | 非生產窗口殘餘流量中位數 ÷ 生產平均流量 ≥ 10%（注意）/ 20%（顯著） | 流量 × 比功率（P25/P50/P75）× 非生產時數 | 超音波巡檢、保壓衰減測試 |
| S1 | ③ sequencing | 任一台卸載比 > 20% | —（由 S2 量化） | 檢視停機延遲與排序 |
| S2 | ③ | 停機延遲候選 5 / 10 / 15 / 30 分逐段模擬，最佳**可行**候選省電 > 0 | 每段卸載超過延遲的分鐘 × 實測卸載 kW | 縮短停機延遲試驗 |
| S3 | ③ | 每運轉小時循環次數 P95 > 參考線 10 次/h | — | 加寬壓力帶 / 儲氣 |
| S4 | ③ | 多機運轉時，兩台以上同時部分負載占比 > 20%（單台系統：不適用） | 不量化（需多機組合試算） | 檢視排序 |
| S5 | ③ | VSD 滿載（≥ 95%）而定頻機卸載的時間占比 > 10% | — | VSD 設為調節機 |
| S6 | ③ | 運轉 ≥ 1 h 但加載 < 1% 的機台 | 該機運轉 kWh | 改備援停機 |
| E1 | ④ equipment-fit | 基準期 vs 分析期同工況（流量 10 格 × 壓力 0.5 bar）比功率差異，區間下限 > 0 且中心 > 5% | 分析期 kWh × D ÷ (100 + D) | 保養檢查 |
| E2 | ④ | 定頻：加載率 < 50% 且頻繁循環；VSD：最低負載附近時間 > 30% | — | 評估較小調節機 / 儲氣 |
| E3 | ④ | 全部機台滿載仍低於需求壓力 ≥ 30 分 | — | 先處理洩漏再評估擴容 |
| E4 | ④ | 設備層 ControlType = 進氣節流 | — | 依平均負載建議換 VSD（< 60%）或定頻 + 儲氣 |

規則狀態：觸發 / 未觸發 / 資料不足（點名缺什麼，不出數字）/ 待補場域資料（需求壓力、生產時段）/ 待設定（劣化基準期）/ 不適用。

**加卸載狀態**：有可信 LOADED 點用之；否則運轉中 kW ≥ 判定額定 × 20% 視為加載（標「推定」）。判定額定 = 銘牌 RatedPower，未填用觀測最大 kW。定頻機卸載功率常在額定 20–30%，邊界會有誤判 → 建議綁 LOADED 點。
**控制型式**：設備層欄位優先；未填由運轉中 kW 分佈推定（kW / 額定落在 45~85% 的時間 < 20% → 定頻雙峰，否則 VSD），標「推定」。節流機型不推定（功率分佈無法可靠區分）。

### 12.2 區間（全部確定性）

| 規則 | 中心 | 低 ~ 高 |
|---|---|---|
| L 殘餘流量 | 各非生產窗口中位數 | 窗口 < 10：最小 ~ 最大；≥ 10：P10 ~ P90 |
| L → kWh | 中位流量 × 比功率 P50 | 流量低 × P25 ~ 流量高 × P75（運轉小時全場比功率分佈） |
| P | 可降 bar × 5.5% | × 5% ~ × 6% |
| S2 | 逐分鐘實測卸載 kW 加總 | 節省分鐘 × 卸載 kW 的 P25 ~ P75 |
| E1 | 各格差異依分析期 kWh 加權 | ± 1.96 × 合成標準誤 |
| 年化 / NTD | 期間值 × 365 ÷ 天數 × 電價 | 低、高各自年化，不重新組合 |

**重疊旗標**（各項節能不可直接相加）：P + L（降壓後洩漏變小）、S2 + S6（同段卸載時間）、L + S2/S6（非生產卸載空轉兩邊都計）。
**電價**：期間 `ElectricityCostHourly` 實際平均單價（ΣCost ÷ ΣKwh）優先；無（未設方案 / 累進制）→ 設定頁手填；再無 → 只列 kWh。

### 12.3 數值來源與「依預設值」旗標

skill 原則：數值分三類 —— 由資料推導、由場域 / 銘牌提供、拿不到就不出數字並點名缺什麼；原本由 LLM 在 checkpoint 問使用者。本系統改為：**全部參數進設定頁且都有預設值**，每條結論若用到「既沒被覆寫、也沒被工程師按確認」的預設值，結果標 **依預設值（未經現場確認）** 並列出參數名；工程師改值或按「確認」後旗標消失。參數表與出處（skill 原文 / 本系統經驗值）見設定頁「診斷參數」，定義單一真相 = Common `DiagnosisParameters.Definitions`。

### 12.4 場域資料與退回

| 場域事實 | 存放 | 未填時 |
|---|---|---|
| 末端最低需求壓力 | `CompressorDiagnosisSetting` | P / E3 → 待補場域資料 |
| 生產時段（每週排程 + `/HolidaySetting` 假日） | 同上 | L → 待補場域資料 |
| 劣化基準期 | 同上 | E1 → 待設定，結果頁提示「請至診斷設定指定」 |

v1 所有啟用中的空壓機 = 一個系統（不分群）。v1 不做：保壓衰減試算、儲氣桶篩算、多機最佳組合、設備報價。

### 12.5 執行與權限

- **每日 02:00**（`CompressorDiagnosisSchedulerService`）對「昨日」生成**最近 7 天滾動**快照（`CompressorDiagnosisSnapshot`，IsScheduled=1）；能源日報生成時呼叫同一冪等方法（誰先到誰算，`SemaphoreSlim` 序列化）。無啟用空壓機不算
- 分鐘資料 on-demand：HistoryData 分鐘平均（同 `EquipmentHourlyAggregator` SQL 模式，KWH 累積點不撈）+ `EquipmentHourly`（期間 kWh、比功率分佈、E1 同工況）；不新增逐分鐘表
- **一般使用者**（有頁面權限）：「系統診斷」tab 看最新排程快照 —— 狀態、節能區間、建議下一步、缺什麼、附註、試驗檢查清單、實測基線
- **Engineer**：另見證據數字 + 公式 + S2 候選表，可指定期間（上限 92 天）重算（存 IsScheduled=0 快照）；「診斷設定」tab 維護場域資料 / 系統點位 / 生產時段 / 基準期 / 參數。前端隱藏 + API `PermissionService.IsEngineer` 雙重擋
- **能源日報**：設定頁「空壓系統診斷」區段（SectionFlags 256，**預設不勾**）；摘要（只列觸發規則 + NTD/年區間 + 下一步 + 附註）於日報生成時依全局語言渲染進快照，Email 與 /DailyReport 讀同一份
