# 功能說明書 — 用水報表（自來水表迴路設定 + 用水報表）

> ⚠️ 本功能處理**累積式水表**（讀數單調遞增的 m³ / L 水量表），全體系採 `WaterMeter*` 前綴。
> 與既有 `/ChilledWaterSystem`（空調水系統冷凍噸 RT，`WaterCircuit` / `WaterLeafHourly`）**完全無關**。
> 跨模組資料流總覽見 [架構.md](架構.md) §用水報表與水費計算。

## 1. 自來水表迴路設定（/WaterMeterSetting）

比照電表 `/EnergyMeter` 的自參照樹：虛擬節點（不綁 SID）做階層分組，葉子綁實體點位。

| 欄位 | 用途 |
|------|------|
| SID | 葉子綁 Modbus / Calculated / DB 點位；虛擬節點為 NULL |
| UnitScale | 點位原始單位 → m³ 換算係數（m³ 系=1、L 系=0.001）。**綁定時依點位單位定案**，事後改點位單位字串不追溯改義 |
| MaxVolume | 水表累積讀數溢位上限（**以點位原始單位計**）；讀數倒退且有設 → 套環繞公式，未設 → 該小時 delta=0 並記警告 |
| Sign | 對父節點貢獻方向 ±1（總表 − 已分配子表等算式）；根節點強制 +1 |

- **點位下拉自動過濾水量單位**：只列 `WaterMeterCircuitService.ResolveUnitScale(unit) != null` 的點位。篩選說明收在「水量點位」旁 `?` 圖示的 tooltip、點位圖示 `fa-tint`；選擇器清單只顯示「名稱 / 單位 × 係數」，不顯示 SID，搜尋只比對名稱。
  單位關鍵字（不分大小寫、常數表可擴充）：`m³ / m3 / cmd / cms / 立方公尺 / 立方米 / 米立方` → 1；`L / liter / litre / 公升 / 升` → 0.001。
  **「度」刻意不納入**（與電度混淆）— 現場水表點位若單位標成「度」，先在點位管理改成 m³。
- **拖曳搬移**：樹節點可拖曳換序或跨層搬到別的父節點底下；水表體系**單一根**（全廠），根節點不可拖、不能拖出第二個根（前端擋 + 後端 `sort_multi_root`）；跨層 / 放到實體水表底下會先 confirm。規則全文見 [功能說明書_階層樹拖曳搬移.md](功能說明書_階層樹拖曳搬移.md)
- 刪除節點：有子節點時前端二次確認（`?force=true`），後端遞迴 CTE 一次刪除所有子孫。
  `WaterMeterLeafHourly` 以 SID 為 key，迴路刪除後 hourly 列成為孤兒但不再被查詢引用（比照 EnergyCircuit 現行做法，可容忍不主動清）。
- 資料表：`WaterMeterCircuit`（DatabaseSchema.json 自動建表）。

## 2. Engine 葉子層 hourly 預聚合

`ScadaEngine.Engine/Services/`：

- **WaterMeterLeafAggregator** — 純邏輯：單 SID × 單小時取 [hourStart, +1hr) 兩邊界值（HistoryData 最近一筆、staleness window 預設 2h、Quality=1）→ 原始單位相減 + MaxVolume 溢位 → × UnitScale 輸出 m³。
  純邏輯入口 `ComputeFromBoundaries` / `CalcDeltaWithRollover` 為 public static，單元測試（`ScadaEngine.Tests/WaterMeter/WaterMeterLeafAggregatorTests.cs`）直接鎖規則。
- **WaterMeterLeafAggregationService** — BackgroundService：XX:02 觸發聚合上一小時 + 啟動 catch-up（預設 24h，缺漏才補）。斷線恢復不會把累積差灌進單一小時（staleness window 擋掉，恢復首小時記 Q=0 transition）。
- **WaterMeterLeafHourlyRepository** — MERGE UPSERT + 從 `WaterMeterCircuit` 查葉子清單（SID + MaxVolume + UnitScale）。

Sparse storage 三段語意（同電表）：兩邊界有值 → Q=1；只缺一邊 → Q=0、Delta=0（掉線 transition）；兩邊都缺 → 不寫該列。

設定鍵（appsettings.json）：`WaterMeterAggregation:MaxStalenessHours`（預設 2）、`WaterMeterAggregation:CatchUpHours`（預設 24）。

## 3. 用水報表（/WaterUsageReport）

- 粒度：時(日視圖)/日(月視圖)/月(起訖月)/年(起訖年)/**班別**(起訖日)，**月粒度走 `WaterBillingPeriods` 水費期別**（`WaterBillingPeriodService`，於 `/WaterBillingPeriodSetting` 維護）；**班別粒度**依 `/ShiftSetting` 班別定義分段（每列 = 日期 × 班別 + 非班別補桶，跨日班歸起始日），細節見 docs/功能說明書_班別設定.md。
  ⚠️ **與電費期別完全獨立** — 台水與台電抄表日不同，改電費期別不會動到用水報表，反之亦然。期別設定改動即時生效、歷史月報自動重算。
- 計算：`WaterUsageReportService` **直接加總 `WaterMeterLeafHourly`**（per-bucket `SUM(DeltaM3 × EffectiveSign)`）；sign / 階層 / 虛擬節點 on-demand 在 Web 端套，迴路結構改變即時生效不需回填。
- 葉子綁 L（公升）點位時聚合已換算，**報表一律以 m³ 呈現**。
- bucket 內任一葉子有 Q=0 列 → 該 bucket 標 stale（前端 hover 提示資料不完整）。
- Excel 匯出：`WaterUsageReportExcelExporter`（ClosedXML，含子迴路多欄展開，i18n resx）。

## 4. EMS 首頁卡片

三張卡（`EmsCardRegistry` 註冊，`/EmsCardSetting` 可顯示/隱藏/排序）：

| CardKey | 內容 |
|---------|------|
| `WaterUsageBar` | 用水量長條圖（日/月/年切換；全廠 = 樹根節點） |
| `WaterUsagePie` | 根節點直接子迴路用水占比圓餅圖 |
| `WaterCost` | 水費狀態卡（本期用水 + 級距明細，見 [功能說明書_水費設定.md](功能說明書_水費設定.md)） |

無主水表（IsMainMeter）概念 — 「全廠用水」= 樹根節點加總。
JS：`wwwroot/js/ems-hub-water.js`（一支驅動三卡，各卡以根元素存在防呆）。
API：`GET /EMS/api/water-circuit-tree` / `water-usage` / `water-breakdown` / `water-cost`。
