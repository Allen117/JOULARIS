# 功能說明書：系統參數 (SystemParameter)

## 1. 功能概述

工程師專屬的通用參數頁，集中存放「依現場實測調整」的系統上限與門檻，避免把數字寫死在程式碼、也避免為單一參數各開一頁。存檔後下一個請求即生效，不需重啟服務。

## 2. 路由與權限

| 方法 | 路由 | 說明 |
|------|------|------|
| GET | `/SystemParameter` | 頁面 |
| GET | `/SystemParameter/api/config` | 目前值 + 預設值 + 最後更新時間 |
| POST | `/SystemParameter/api/config` | 整份儲存（範圍驗證失敗回 400 + `code` = resx key） |

- **僅 Engineer**：列在 `PermissionService.EngineerPages`（頁面由 `PageAccessFilter` 擋 Admin / User 並導向 AccessDenied），Controller 另掛 `[Authorize(Roles = "Engineer")]` 擋 API 直連
- 選單位置：導覽列「工程師模式」→「系統參數」；全站搜尋可找到（僅 Engineer）

## 3. 參數一覽

| 參數（JSON 屬性） | 預設 | 範圍 | 使用處 |
|---|---|---|---|
| `nHistoryMaxRecordsPerPoint` 每點位最多筆數 | 5,000 | 100 ~ 100,000 | 歷史趨勢查詢與匯出共用（取代原 `HistoryController` 寫死的 5000） |
| `nHistoryExportMaxCells` 匯出儲存格上限 | 50,000 | 1,000 ~ 1,000,000 | 歷史趨勢匯出前檢查 Σ點位 × 預估筆數，超過擋下（不查 DB） |
| `dCumulativeJitterTolerancePct` 累計值抖動容差 | 1 % | 0 ~ 50 | 累計值差異值：降幅 ≤ \|前值\| × 容差% 視為抖動，超過才判定歸零 / 換表 |

各參數細節見 [功能說明書_歷史趨勢.md](功能說明書_歷史趨勢.md) §2 匯出 API、§8.2 差異值、§10 匯出上限。

## 4. 儲存

- 沿用既有 `SystemSettings` 表（SettingKey / SettingValue / UpdatedAt），key = `system_parameters`，value 為整份 JSON（同 `gas_tariff` 模式），**不新增資料表**
- **缺鍵補預設**：模型屬性初始值即預設值，DB 內舊 JSON 缺新參數時反序列化自動補上，不需遷移
- DB 無值 / JSON 損毀 / 讀取失敗 → 一律回預設值並記 log，不擋住呼叫端功能
- 每次呼叫都讀 DB（單筆 key 查詢），無快取 → 存檔即生效

```
wwwroot/js/systemparameter.js、wwwroot/css/systemparameter.css
Resources/Features.SystemParameter.Views.Index{,.en}.resx
```

## 6. 新增參數 SOP

1. `SystemParameterConfig` 加屬性（初始值 = 預設值）
2. `SystemParameterLimits` 加範圍，`SystemParameterService.Validate` 加檢查（錯誤回 `sysparam.error.*` key）
3. `Index.cshtml` 加一列 `<input data-key="屬性名">`（JS 依 `data-key` 自動讀寫，不用改 JS）
4. zh-TW / en resx 同步補字串
5. 使用端注入 `SystemParameterService` 呼叫 `GetAsync()`
6. 本文件 §3 補一列；單元測試 `SystemParameterTests` 補範圍案例
