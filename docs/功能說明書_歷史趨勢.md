# 功能說明書：歷史資料 (HistoryData)

## 1. 功能概述

歷史資料頁面提供**多點位時間序列資料查詢與視覺化**能力，使用者可選取 Modbus / 計算 / DB 來源點位，指定時間範圍與取樣間隔後查詢 HistoryData 資料表，以折線圖或柱狀圖呈現歷史數據，並附帶統計摘要與 Excel 匯出功能。

### 核心能力
- **多點位並行查詢**：最多同時查詢 8 個點位，每個點位上限預設 5000 筆（工程師可於 [系統參數](功能說明書_系統參數.md) 調整）
- **時間間隔取樣**：可選原始 / 1m / 5m / 15m / 30m / 1h，**對整點對齊取每 bucket 首筆**（不平均），便於長區間概覽
- **三種圖表模式**：單點（主圖 + 資料明細表）、雙點（雙 Y 軸）、多點（堆疊小圖）
- **統計分析**：最小值、最大值、平均值、標準差（**只算 Quality=Good**）；累計值（kWh、m³…）另算**差異值**（分段相加，處理歸零 / 換表）— 後端 `HistoryStatisticsCalculator` 單一實作，畫面與匯出一致
- **品質標示**：Bad 品質點位以紅色標記，圖表以 hold-last-good 策略維持曲線連續
- **Excel 匯出**：伺服器端產檔（ClosedXML + OpenXml SDK），每次都含「統計」+「圖表」分頁 + 各點位資料分頁；圖表依點位類型 × 單位自動產生（累計值長條 / 圓餅、即時值折線）
- **跨頁整合**：接收 ScadaPage 趨勢圖右鍵選單透過 localStorage 傳入的預載點位

## 2. 路由

| 方法 | 路由 | 說明 | 認證 |
|------|------|------|------|
| GET | `/HistoryData` | 歷史資料頁面 | 需登入 |
| GET | `/api/history/data` | 查詢歷史資料 API | 需登入 |
| POST | `/api/history/export` | 匯出 Excel（統計 + 圖表 + 資料分頁） | 需登入 |

### API 參數與回應

#### GET `/api/history/data`

**查詢參數**：

| 參數 | 型別 | 說明 |
|------|------|------|
| `szSID` | string | 點位 SID（必填） |
| `szStart` | string | 開始時間（ISO 格式，預設 24 小時前） |
| `szEnd` | string | 結束時間（ISO 格式，預設現在） |
| `nInterval` | int | 取樣間隔（分鐘），預設 0。`0` = 原始；`>0` = 對 `Timestamp` 按 N 分鐘對齊整點分 bucket，每 bucket 取最早一筆 |

**回應格式**：

```json
{
  "success": true,
  "szSID": "196865-S1",
  "szName": "溫度感測器",
  "szUnit": "°C",
  "nCount": 1440,
  "nValidCount": 1432,
  "nMaxRecords": 5000,
  "isLimited": false,
  "szPointKind": "Instant",
  "szUnitGroup": "°C",
  "dMin": 22.5,
  "dMax": 28.3,
  "dAvg": 25.12,
  "dStdDev": 1.83,
  "dDiff": null,
  "nDropCount": 0,
  "nSpikeCount": 0,
  "isStartInset": false,
  "isEndInset": false,
  "data": [
    { "t": "2026-03-30T08:00:00", "v": 25.3, "q": "Good" },
    { "t": "2026-03-30T08:01:00", "v": 25.1, "q": "Good" }
  ]
}
```

| 欄位 | 說明 |
|------|------|
| `nCount` / `nValidCount` | 實際資料筆數 / 有效筆數（Good 且為有限數） |
| `nMaxRecords` / `isLimited` | 每點位筆數上限（系統參數）/ 是否達上限被截斷 |
| `szPointKind` | 點位類型：`Instant` 即時值 / `Cumulative` 累計值 / `Period` 期間值 / `Status` 狀態值（見 §8.1） |
| `szUnitGroup` | 單位分組（累計值為正規化單位 kWh / MWh / Wh / RTh / m³ / Nm³） |
| `dMin` / `dMax` / `dAvg` / `dStdDev` | 只用有效值計算；標準差為**母體**標準差；整段無有效值時皆為 `null` |
| `dDiff` | 累計值差異值（非累計值為 `null`，見 §8.2） |
| `nDropCount` / `nSpikeCount` | 判定為歸零 / 換表的次數 / 剔除的單筆突波數 |
| `isStartInset` / `isEndInset` | 首筆 / 末筆有效值距查詢起訖超過一個取樣間隔（差異值起訖往內找） |
| `data[].t` | 時間戳記（ISO 格式） |
| `data[].v` | 數值 |
| `data[].q` | 品質（`Good` / `Bad`） |

#### POST `/api/history/export`

**Body**：`{ "sids": [...], "szStart": "...", "szEnd": "...", "nInterval": 1 }` — 與趨勢頁查詢同一組參數（前端記下查詢當下的值，匯出沿用，內容與畫面一致）。

1. 預估儲存格數 = Σ每點位 min(期間分鐘數 ÷ max(間隔, 1), 每點位筆數上限)，**只用時間計算、不查 DB**
2. 超過系統參數「匯出儲存格上限」（預設 50,000）→ 回 `400 { code: "export_limit", nEstimatedCells, nMaxCells }`，前端顯示「預估 N 格，超過上限 M 格…」
3. 未超過 → 逐點位重查 + 統計 → `HistoryExcelExporter` 產檔 → 回 `.xlsx`（檔名 `歷史趨勢_yyyyMMdd_HHmm.xlsx`，英文介面為 `Trend_…`）

> 兩層限制：每點位筆數上限（查詢與匯出共用）+ 儲存格上限（總量最後防線）。現況 8 點位 × 5,000 = 40,000 不會觸發後者；日後放寬每點位筆數或購物籃數量才起作用。

    ├─ Razor SSR ──────────────────────────────────────────
    │   ├─ window.__historyConfig.points       ← JSON 點位陣列
    │   ├─ window.__historyConfig.coordinators ← JSON 設備陣列

    │
    ├─ JS 初始化 ──────────────────────────────────────────

    │
    └─ 使用者操作 ─────────────────────────────────────────
        ├─ 側欄篩選設備     → renderPointList() 更新點位清單

## 5. 控制器說明

### HistoryController

#### `HistoryData()` — 頁面入口

1. 查詢所有 Coordinator（側欄用）+ DB Coordinator
2. 查詢所有 Modbus 點位 + 啟用的計算點位 + DB 來源點位（合併為單一清單）
3. 提取計算點位的群組名稱（供側欄分群）
4. 建構 `CalcGroupMap`（SID → GroupName 對照）
5. 預設時間：過去 24 小時

#### `GetHistoryData()` — 資料查詢 API

1. 驗證 SID 非空、時間範圍合法、`nInterval >= 0`
2. 讀系統參數（每點位筆數上限、抖動容差）
3. `HistoryQueryService.ResolvePointsAsync` 查點位名稱與單位（Modbus → `CALC-` 計算點位 → `DB` 來源 → `OPC` → `DMD-` 需量虛擬點位）
4. `HistoryQueryService.QueryPointAsync` → `GetHistoryTableDataAsync(szSID, dtStart, dtEnd, 上限, nInterval)`
   - `nInterval = 0` 走原 SQL 路徑
   - `nInterval > 0` 走 `ROW_NUMBER() OVER (PARTITION BY bucket ORDER BY Timestamp ASC)` 的 bucket SQL，bucket 公式：`DATEADD(MINUTE, DATEDIFF(MINUTE, 0, Timestamp) / @IntervalMin * @IntervalMin, 0)`
5. `HistoryStatisticsCalculator.Calculate` 算分類 + 統計 + 差異值
6. 回傳 JSON（含 `isLimited` 標記是否截斷）

#### `Export()` — 匯出 API

見 §2 POST `/api/history/export`。

## 7. 前端邏輯 (history.js)

以 IIFE 封裝，對外暴露 `window._history`（`exportToExcel`、`removeFromBasket`）。

### 7.1 初始化

1. 從 `window.__historyConfig` 讀取 Razor 注入的資料
2. `enrichPointsWithDeviceLabel()`：依 SID 數值範圍比對 Coordinator/SubDevice，為每個點位加上 `deviceLabel`（設備名稱）和 `fullName`（`設備/點位名稱`）
3. 檢查 `localStorage['SCADA_TREND_PRELOAD']`，若存在則自動加入 Basket 並刪除

### 7.2 設備側欄

與即時數據頁面相同的三種點擊事件：
- **單一設備** (`coordinator-item`)：篩選該設備下所有點位
- **展開/收合** (`coordinator-toggle`)：展開子設備列表 + 篩選
- **子設備** (`sub-item`)：篩選特定 ModbusID 或計算點位群組

**計算點位特殊處理**：
- `data-id="-999"` 表示計算點位
- 支援群組篩選 (`data-calcgroup`)
- 無群組的計算點位歸類為「未分組」

### 7.3 點位選取與 Basket

**兩階段選取**：

1. **勾選點位**：左側點位清單，checkbox 多選
2. **加入 Basket**：按「加入待查詢清單」按鈕移入

**Basket 規則**：
- 最多 8 個點位 (`MAX_BASKET = 8`)
- 不可重複加入（依 SID 判斷）
- 可跨設備加入
- 每項顯示色彩圓點（對應圖表顏色）
- 可個別移除或全部清除

**色彩常數** (8 色循環)：

| 索引 | 色碼 | 用途 |
|------|------|------|
| 0 | `#0d6efd` (藍) | 第 1 個點位 |
| 1 | `#dc3545` (紅) | 第 2 個點位 |
| 2 | `#198754` (綠) | 第 3 個點位 |
| 3 | `#ffc107` (黃) | 第 4 個點位 |
| 4 | `#0dcaf0` (青) | 第 5 個點位 |
| 5 | `#6f42c1` (紫) | 第 6 個點位 |
| 6 | `#fd7e14` (橘) | 第 7 個點位 |
| 7 | `#6610f2` (靛) | 第 8 個點位 |

### 7.4 查詢流程 (`doQuery`)

1. 驗證：Basket 不為空、時間範圍合法
2. 讀取「時間間隔」下拉值（`#selInterval`，0 = 原始）
3. 顯示 Loading spinner
4. `Promise.all`：並行呼叫 `/api/history/data?...&nInterval=N` 查詢每個 Basket 中的點位
4. 處理回應：
   - 任一失敗 → 顯示錯誤訊息
   - 全部無資料 → 顯示「該時段內無歷史資料」
   - 有資料被截斷 → 顯示黃色警告 Badge
5. 根據有效點位數量決定顯示模式（見 7.5）
6. 更新統計卡片 / 統計表格
7. 顯示匯出 Excel 按鈕
8. 單點模式額外顯示資料明細表

### 7.5 圖表渲染模式

| 有效點位數 | 圖表模式 | 特殊功能 |
|-----------|----------|---------|
| **1 個** | 單一主圖（380px） | 統計卡片（Min/Max/Avg/StdDev）、資料明細表、品質紅色標點、面積填充 |
| **2 個** | 雙 Y 軸主圖 | 左右軸分別對應不同點位，可切換單軸/雙軸模式 |
| **≥3 個** | 堆疊小圖（每個 170px） | 每個點位獨立 Y 軸，共用 X 時間軸（僅最後一個小圖顯示 X 刻度） |

### 7.6 Chart.js 配置

**時間軸**：
- 使用 `date-fns` adapter
- 顯示格式：秒 → `HH:mm:ss`、分 → `MM-dd HH:mm`、時 → `MM-dd HH:mm`、日 → `MM-dd`
- Tooltip 格式：`yyyy-MM-dd HH:mm:ss`

**品質處理 (`holdLastGoodValue`)**：
- Bad 品質的資料點在圖表上使用前一個 Good 值，保持曲線連續
- 原始值保留供 Tooltip 顯示
- 單點模式下 Bad 品質點以紅色標記

**效能最佳化**：
- 資料量 > 500 筆：隱藏圓點 (`pointRadius: 0`)
- 資料量 > 1000 筆：停用動畫 (`animation.duration: 0`)

**雙 Y 軸**：
- 左軸 (`y`)：第 1 個點位，軸標題顯示單位
- 右軸 (`y1`)：第 2 個點位，不繪製網格線
- 各軸自動計算 ±10% padding 的量程範圍

### 7.7 單軸/雙軸切換

僅在 **2 個有效點位** 時顯示切換按鈕：
- **雙軸模式**（預設）：兩個點位各自 Y 軸，量程獨立
- **單軸模式**：兩個點位共用左側 Y 軸
- 切換時以 `lastResults` 快取重建圖表，無需重新查詢 API

### 7.8 圖表類型切換

- **折線圖** (`line`)：預設，單點模式含面積填充
- **柱狀圖** (`bar`)
- 切換時觸發 `doQuery()` 重新查詢與渲染

## 8. 統計顯示

統計一律由後端 `HistoryStatisticsCalculator` 計算（趨勢頁 API 與匯出「統計」分頁同一支），前端只顯示。

**有效值** = `Quality == Good` 且為有限數（排除 NaN / ±Infinity）。本系統斷線時寫 Bad 並保留最近成功值，Bad 列的值是舊值，計入會讓斷線越久標準差越被低估，故一律排除。

### 單點模式：統計卡片

四張色彩卡片橫排顯示（累計值多一張「差異值」）：

| 指標 | 背景色 | 圖示 |
|------|--------|------|
| 最小值 | `#198754` (綠) | `fa-arrow-down` |
| 最大值 | `#dc3545` (紅) | `fa-arrow-up` |
| 平均值 | `#ffc107` (黃) | `fa-chart-bar` |
| 標準差 | `#0dcaf0` (青) | `fa-wave-square` |
| 差異值 | — | 僅 `dDiff != null`（累計值）顯示 |

### 多點模式：統計表格

使用 `table-dark` 表頭的表格，欄位：點位、最小值、最大值、平均值、標準差；任一點位為累計值時多「差異值」欄（非累計值顯示 `--`）。

### 8.1 點位分類（`PointKindClassifier`）

依序判斷，命中即停：

| 順序 | 條件 | 類型 |
|---|---|---|
| 1 | 名稱含 今日／本日／本月／昨日／上月／today／yesterday／this month／last month | 期間值（不算差異值、不畫圖） |
| 2 | 單位（trim、小寫）**完全等於**累計單位別名之一 | 累計值，歸到 kWh / Wh / MWh / RTh / m³ / Nm³ 組 |
| 3 | 單位為空，名稱含獨立的 kWh／MWh／RTh／Nm3／m3（前後不接英數字、名稱不含「/」） | 累計值（後備） |
| 4 | 有效值全為 0 或 1 | 狀態值（不畫圖；平均值即運轉率） |
| 5 | 其餘 | 即時值，依 trim 後單位分組（單位空 → 每點位自成一組） |

- 單位採**完全比對**：`m3/h`、`kWh/m3` 不會被當累計值；名稱後備要求前後不接英數字，`North`、`AHM3` 不會誤判。
- 累計單位別名沿用原前端 `KWH_UNIT_ALIASES`（含「度」「用電度數」等），另補 RTh、m³、Nm³ 別名。Wh / MWh 與 kWh 量級不同，各自成組。

### 8.2 累計值差異值（分段相加）

依時間走過有效值：

| 情況 | 判定 | 處理 |
|---|---|---|
| 突波 | `v[i] > prev` 且 `v[i+1] < v[i]` 且 `v[i+1] >= prev` | 丟掉 `v[i]`（只處理**單筆**，連續 2 筆以上不處理） |
| 抖動 | `v < prev` 且降幅 ≤ `|prev| × 抖動容差%`（系統參數，預設 1%） | 丟掉 `v`，`prev` 不更新 |
| 下降 | `v < prev` 且超過容差 | 視為歸零 / 換表：結算本段、以 `v` 開新段 |

差異值 = Σ(段末 − 段初)。只有 1 筆有效值 → 0；無有效值 → 空。首筆 / 末筆有效值距查詢起訖超過一個取樣間隔（間隔 0 視為 1 分鐘）時標示「起點 / 終點往內找」，匯出備註會寫出實際起訖時間。

> 舊版用「最大 − 最小」，遇歸零 / 換表會算錯，已淘汰。

驗收案例（單元測試 `HistoryStatisticsCalculatorTests` 鎖住）：`Bad,100,110,5,20,Bad` → 25、下降 1 次；`100,110,99999,120` → 20、突波 1 筆；`1000,999.9,1001` → 1、不算下降。

## 10. Excel 匯出

伺服器端產檔（`POST /api/history/export`，見 §2）。原本瀏覽器端用 SheetJS 社群版，但它**不能寫圖表**；ClosedXML 0.102 也不支援圖表，故改為 ClosedXML 寫表 → `HistoryExcelChartWriter` 以 DocumentFormat.OpenXml（ClosedXML 相依、已在專案內，未新增套件）後處理加圖表。

### 匯出內容（每次都有，不詢問；單點位也有）

| 順序 | 分頁 | 內容 |
|---|---|---|
| 1 | 統計 | 查詢期間 / 取樣間隔；每點位一列：點位名稱、單位、類型、筆數、有效筆數、最小 / 最大 / 平均 / 標準差、差異值、備註 |
| 2 | 圖表 | A～C 累計點位資料表（點位名稱、差異值、單位）+ 圖表 |
| 3… | 各點位 | 時間戳記、數值（含單位）、品質、**有效值**（Good 才填，Bad 留空）；無資料的點位不建分頁 |

- 分頁名取點位名稱（去除 `[]:*?/\`、截至 31 字、重複加序號）
- 備註：整段無有效資料 / 達每點位筆數上限 / 狀態值「平均值即運轉率」/ 歸零換表 N 次 / 剔除突波 N 筆 / 起點、終點往內至某時間

### 圖表規則

| 點位類型 | 圖表 | 規則 |
|---|---|---|
| 累計值 | 長條圖 | 每單位組一張；柱頂標值 `0.00`；無圖例；類別軸標籤 Low |
| 累計值 | 圓餅圖 | 每單位組一張，僅當差異值 > 0 的點位 ≥ 2 個；標百分比；圖例在下 |
| 即時值 | 折線（XY 散佈圖直線連接） | 每單位組一張（單位空 → 每點位一張）；各數列參照自己資料分頁的時間欄與「有效值」欄 → Bad 處自然斷線（`dispBlanksAs=gap`），不畫舊值 |
| 期間值 / 狀態值 | 不畫 | — |

- 圖表資料表同單位相鄰、組內差異值為 0 者排組尾（圓餅需連續範圍，只參照非零段）
- 所有圖表**參照儲存格**（改數字圖會跟著變）並附 strCache / numCache（不重算也能顯示）
- 排列：長條 → 圓餅 → 折線，從 E1 往下，每張 22 列高、間隔 1 列
- 每條線點數 = 該點位筆數（受每點位筆數上限約束），不另做降頻
- 無任何可畫圖表時，圖表分頁 A1 寫說明文字
- 讀回測試 `HistoryExcelExporterTests` 鎖住分頁組成、統計值、圖表數量、cache 與 OpenXml schema 驗證無錯；Excel 與 LibreOffice 皆實開確認

### 上限

匯出前檢查「Σ點位 × 預估筆數 ≤ 匯出儲存格上限」（系統參數，預設 50,000），超過擋下並顯示預估格數與上限，不查 DB。伺服器記憶體估計 5 萬格約 50～100 MB，實測後可由工程師在 [系統參數](功能說明書_系統參數.md) 調整。

### 檔名格式
`歷史趨勢_YYYYMMDD_HHmm.xlsx`（英文介面 `Trend_YYYYMMDD_HHmm.xlsx`）

## 11. 快速時間範圍

查詢條件區提供快速設定按鈕：

| 按鈕 | data-hours | 效果 |
|------|-----------|------|
| 1h | 1 | 最近 1 小時 |
| 6h | 6 | 最近 6 小時 |
| 24h | 24 | 最近 24 小時 |
| 3天 | 72 | 最近 3 天 |
| 7天 | 168 | 最近 7 天 |

點擊後自動填入開始/結束時間（結束時間為當下）。

### 時間間隔下拉 (`#selInterval`)

位於時間範圍區域結束時間下方。選項：

| value | 顯示 | 行為 |
|-------|------|------|
| `0` | 原始（預設）| 不取樣，回傳區間內所有 raw 紀錄（上限 5000） |
| `1` | 1m | 每分鐘整點分 bucket，取首筆 |
| `5` | 5m | 每 5 分鐘對齊（`HH:00 / HH:05 / HH:10 / ...`） |
| `15` | 15m | 每 15 分鐘對齊 |
| `30` | 30m | 每 30 分鐘對齊 |
| `60` | 1h | 整點對齊 |

切換間隔後**不會自動重查**，需按「查詢」按鈕生效。

## 12. 跨頁整合

### 深連結（URL 參數，2026-10-01）

```
/HistoryData?sid=196865-S1&hours=1
/HistoryData?sid=A&sid=B&start=2026-10-01T08:00&end=2026-10-01T12:00
```

| 參數 | 說明 |
|------|------|
| `sid` | 可重複或逗號分隔；帶入待查詢清單（名稱 / 單位從 `allPoints` 補） |
| `hours` | 近 N 小時（終點為現在、進位到整分）；缺省或無效 = 1 |
| `start` / `end` | `yyyy-MM-ddTHH:mm`（本地時間），兩者皆有效且 start < end 時優先於 `hours` |

`history.js` 在 `DOMContentLoaded` 末段 `applyDeepLink()` 解析：帶入 basket → 設 flatpickr 時間 → 等 i18n 字典就緒後自動 `doQuery()`。ScadaPage 右鍵「歷史趨勢（開新頁）」與快速趨勢窗的「開新頁」按鈕即用此連結。無 `sid` 參數時完全不影響原行為（與下方 localStorage 預載並存）。

### ScadaPage → HistoryData 趨勢圖預載

**寫入端**（ScadaPage）：
```javascript
localStorage.setItem('SCADA_TREND_PRELOAD', JSON.stringify({
    sids: [{ sid: "196865-S1", name: "溫度", unit: "°C" }]
}));
```

**讀取端**（History）：
1. `DOMContentLoaded` 時檢查 `localStorage['SCADA_TREND_PRELOAD']`
2. 若存在，解析並自動加入 Basket
3. 從 `allPoints` 補充完整名稱（`fullName`）與單位
4. 讀取後立即刪除 localStorage key
