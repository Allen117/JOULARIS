# 功能說明書：部署與遠端更新（framework-dependent 瘦身包）

## 為什麼要瘦身

早期一包 release 約 **533MB**，遠端更新（USB／雲端硬碟／VPN，不一定有 SSH）搬運痛苦。拆解後發現：

| 區塊 | 大小 | 更新頻率 |
|------|------|----------|
| 自己的 `ScadaEngine.*.dll`（三 app 全部） | **5.9 MB** | 每次都變 |
| .NET 8 self-contained runtime × 3（各 app 夾一份 ~130MB） | ~390 MB | 幾乎不變 |
| PythonRuntime（可攜 Python，只 Engine LogicFlow 用） | 62 MB | 幾乎不變 |
| wwwroot / 預編譯 views / NuGet 相依 | 數十 MB | 偶爾變 |
| LicenseBridge（net48） | 9 MB | 幾乎不變 |

每次更新真正變的只有 ~6MB，卻要搬 533MB。瘦身兩步：

1. **三 app 改 framework-dependent**：不再各夾一份 runtime，改由目標機安裝一份共用 runtime → 砍 ~350MB。
2. **PythonRuntime 抽成獨立基礎包**：帶版號，只在缺或版本變更才鋪 → 常態 app 更新省 62MB。

結果全包從 533MB 降到約 **180MB**；用 `-NoPython` 產 app-only 更新包再省 62MB。

---

## 兩層包模型

```
基礎層（一年動一兩次，多半只在首裝時鋪）
  ├─ ASP.NET Core Runtime 8.0.x   ← 裝進作業系統，三 app 共用；不隨 release 附帶
  └─ PythonRuntime 基礎包 62MB    ← 隨 release 附在「package 根目錄」，帶 VERSION 版號

App 層（每次更新要搬的東西）
  └─ ScadaEngine.*.dll + NuGet 相依 + wwwroot + views
     其中「自己寫的碼」只有 5.9MB
```

## Runtime 前置需求（重要）

三個 .NET 8 app（Engine / Web / ModbusServer）改為 **framework-dependent**，目標機**必須先安裝 .NET 8 共用 runtime**。

- 安裝**一包就全包**：`ASP.NET Core Runtime 8.0.x (x64)`。它內含基礎 .NET Runtime（Engine 用）+ ASP.NET Core 共用框架（Web / ModbusServer 用），一次覆蓋三個 app。
- 下載：<https://dotnet.microsoft.com/download/dotnet/8.0> → 選「ASP.NET Core Runtime」Windows x64。
- **air-gapped 現場**：把離線 installer 放進 USB 隨包攜帶（與 net48 離線安裝作法一致）。
- `Install.bat` 開頭會**偵測**：查不到 `Microsoft.AspNetCore.App 8.x` / `Microsoft.NETCore.App 8.x` 就**印網址並中止，機器維持原狀**，不會裝到一半。

> ⚠️ **只鎖 major = 8**：framework-dependent 預設只在同一 major 內 roll-forward。機器上**只有 .NET 9、沒有 8.x 不會跑**，必須補裝 8.x。

> ⚠️ **既有生產機升級**：目前線上是舊的 self-contained 版，升級到瘦身版**前**要先把 ASP.NET Core Runtime 8 裝上，否則升完服務起不來。SOP：先裝 runtime → 再跑 Install.bat（Install.bat 的偵測會擋住漏裝的情況）。

### self-contained → framework-dependent 切換的殘留檔處理

舊 self-contained 版在 `App` 根目錄放了整套 .NET runtime（`coreclr.dll` / `hostpolicy.dll` / `hostfxr.dll` / `System.*.dll`，Engine ~100MB、Web ~125MB）。若只是 xcopy **覆蓋不刪**，這些殘留 host 檔會讓新的 framework-dependent exe **啟動失敗**（症狀：Engine/Web 服務裝好卻 STOPPED，License 因是 net48 不受影響而 RUNNING）。

Install.bat 於「備份現場設定後、xcopy 前」加了 **clean-root** 步驟：
`for %%F in ("C:\JOULARIS\Engine\App\*") do del`——**只刪 App 根目錄的檔**，子夾（`PythonRuntime`、`Setting`、`Modbus`、`DBPoint`、`OpcUaPoint`、`MqttSetting`、`Algorithms`、`wwwroot`）完全保留，隨後 xcopy 補回全新 app 檔。這根治殘留、也順帶清掉「移除的 NuGet 相依」舊檔。

> 若手動搶修已裝好但起不來的機器：把 `App` 根目錄裡新包沒有的檔搬走（或直接 clean-root）即可，子夾別動。

### 現場設定保留清單（備份/還原）

升級時 Install.bat 備份→還原下列現場設定，**含 OpcUaPoint**（早期版本漏了它，靠 overlay 不刪矇混，加 clean-root 後已正式納入）：

- Engine：`Modbus` / `Setting` / `MqttSetting` / `DBPoint` / **`OpcUaPoint`**
- Web：`Setting` / `MqttSetting`

### 服務啟動類型重設（升級防呆）

`sc create` 在服務**已存在**時直接失敗、不會更新任何設定 —— 若現場曾有人把服務改成「停用」（實例：2026-09-17 生產機 License 服務（當時名 `ScadaEngineLicense`）被停用，重裝後 `net start` 跟著失敗），升級安裝完服務仍是停用狀態。因此 Install.bat / InstallModbusServer.bat 在每個 `sc create` 後固定補一句 `sc config <服務名> start= auto`，把啟動類型硬改回自動（四個服務：Engine / Web / License / Modbus Gateway）。

同理 26.6.0 起再補 `sc config <服務名> binPath= "<%_ROOT%>\...exe"`：既存服務若是舊版安裝程式以其他根目錄註冊的，升級後 binPath 也會被拉回 `%_ROOT%`。

### 安裝根目錄遷移（C:\SCADA → C:\JOULARIS，26.6.0 起）

**根目錄唯一真相**：Install.bat / InstallModbusServer.bat 開頭的 `set "_ROOT=C:\JOULARIS"`，全腳本路徑都由它推導；日後再換只改這一行。程式碼本身**不含任何磁碟根目錄** —— Shared 設定檔、LicenseBridge exe（`LicenseService.ResolveBridgeExePath`）、LogicFlow Algorithms、PythonRuntime、HTTPS 憑證、Web 的 `WatchedFolder`（`../../Engine/App/<X>`）全部以執行檔位置相對推算，所以搬家只需處理「機器上指向舊根的綁定」。

**觸發條件**：Install.bat 偵測到 `%_OLDROOT%\Engine\App`（`C:\SCADA`）存在、且 `%_ROOT%\Engine\App` 不存在 → 先跑 `[0/8]` 遷移，再接一般升級流程（備份 / 還原現場設定、Shared 遷移照舊）。**一次執行完成「搬家 + 升級」**。兩者同時存在時不遷移、只警告並安裝到 `%_ROOT%`（舊夾請人工確認後刪）。InstallModbusServer.bat 也有同樣的遷移段（Gateway 單獨裝在舊根的機器）。

**遷移腳本** `Engine\App\Setting\migrate-install-root.ps1`（Install.bat 直接從 Release 包內呼叫；也可獨立執行，參數 `-OldRoot` / `-NewRoot` / `-SkipRestart` / `-WhatIf`）：

| 步驟 | 動作 | 失敗時 |
|------|------|--------|
| 1 | 列出 binPath 在舊根下的所有服務（新舊服務名、Gateway 皆含），記錄狀態後停止；Path 在舊根下的殘留進程（如 Python）一併結束 | 只警告 |
| 2 | 本機每個執行中 SQL 實例（Windows 驗證，需 sysadmin）查 `sys.master_files`，資料檔在舊根下的 DB → `SET OFFLINE WITH ROLLBACK IMMEDIATE` | 連不上 SQL → 中止（無法確認是否有 DB 檔在舊根）；OFFLINE 失敗 → ONLINE 還原、重啟服務、中止 |
| 3 | `Move-Item C:\SCADA C:\JOULARIS`（同磁碟 = rename，瞬間、原子） | 檔案被鎖 → 列出仍在跑的進程、DB ONLINE、服務恢復、中止（機器維持舊根） |
| 4 | `ALTER DATABASE ... MODIFY FILE (FILENAME=新路徑)` → `SET ONLINE`（不 detach，保留 DB 註冊與權限） | 自動回滾：搬回舊根、改回路徑、ONLINE |
| 5 | 服務 binPath 改指新根（`Win32_Service.Change`，不刪服務 → 保留帳號 / 復原動作設定） | 警告 + 印手動 `sc config` 指令 |
| 6 | 新根下 `*.json` / `*.config` 內的舊根字串改新根（`DbMaintenanceSetting.json` 的資料檔 / 備份路徑、舊版 Web `appsettings.json` 等；排除 PythonRuntime / Log / Database / Backup） | — |
| 7 | 排程工作動作（Execute / Arguments / WorkingDirectory）含舊根者改新根。以 **Task Scheduler COM** 列舉 —— `Get-ScheduledTask` 遇到任一 XML 損壞的任務會整批拋例外 | 以帳密執行的任務無法免密碼更新 → 警告請手動改 |
| 8 | 重新啟動原本在跑、且不在 `-SkipRestart` 內的服務（Install.bat 傳入它自己管的 Engine / Web / License 新舊名，由 `[8/8]` 啟動） | 警告 |
| 9 | 殘留掃描：服務 / 防火牆程式規則 / 環境變數仍含舊根者列出警告（防火牆不自動改） | — |

輸出同時附加到 `<根目錄>\install-log.txt`。腳本**可重跑**：舊根已不存在、新根存在時跳過搬移，只補做 SQL / 服務 / 設定檔 / 排程改指（部分失敗後用）。

**預演**：`powershell -ExecutionPolicy Bypass -File <Release包>\Engine\App\Setting\migrate-install-root.ps1 -WhatIf` —— 只盤點並印出會做什麼（SQL 僅唯讀查詢），不停服務、不搬檔。預演無法驗證 rename 會不會被鎖。

**注意事項**

- 停機窗口：服務停止 → SQL OFFLINE → rename → ONLINE → Install.bat 升級完畢，生產採集中斷約 1–2 分鐘。
- `Move-Item` 失敗最常見原因：檔案總管 / 編輯器 / 命令列視窗開在 `C:\SCADA` 底下、log 檔被開著。關掉後重跑 Install.bat 即可。
- 本機 SQL 資料檔不在舊根下的 DB（例如生產 `wsnCsharp` 在 SQL 預設 DATA 目錄）完全不受影響。
- **遷移後不得再執行 26.5.0 以前的 Install.bat** —— 舊版會在 `C:\SCADA` 做一次全新安裝並把服務 binPath 指回去。若誤跑：用新版 Install.bat 再跑一次（`sc config binPath=` 會把服務拉回 `C:\JOULARIS`、並警告 `C:\SCADA` 殘留），再人工刪 `C:\SCADA`。
- 手動回滾（自動回滾也失敗時）：停服務 → SQL `SET OFFLINE` → `Move-Item C:\JOULARIS C:\SCADA` → `ALTER DATABASE ... MODIFY FILE` 改回原路徑 → `SET ONLINE` → 以舊版 Release 包 Install.bat 重裝。

### 服務命名、角色描述與產品版號（2026-10 起）

**服務名是機器用的識別碼**（穩定、無空白、不含環境），**DisplayName / 描述是給人看的**（角色、版號、建包日期）。四個服務：

| 元件 | 服務名（`sc` / `Stop-Service` 用） | DisplayName | 描述（services.msc） |
|------|------|------|------|
| Engine | `JoularisEngine` | JOULARIS Engine | `JOULARIS Engine \| Backend - data collection (...) \| v26.1.0 \| 2026-10-06` |
| Web | `JoularisWeb` | JOULARIS Web | `JOULARIS Web \| Frontend - web dashboard (http 5038, https 7189) \| v... \| ...` |
| License Bridge | `JoularisLicense` | JOULARIS License Bridge | `... \| Backend - 32-bit HASP verification (Named Pipe, Engine only) \| ...` |
| Modbus Gateway | `JoularisModbusGateway` | JOULARIS Modbus Gateway | `... \| Backend - Modbus TCP gateway (FC4 ...) \| ...`（獨立 InstallModbusServer.bat） |

- **角色標籤**（Backend / Frontend）是元件固有屬性，腳本寫死，不詢問安裝者。HASP 只綁 Engine（LicenseService 驗證），Web 完全不碰授權。
- **描述只用 ASCII**：Install.bat 由 BuildRelease.ps1 以 `-Encoding ASCII` 寫出、cmd 用 OEM codepage 跑，中文會成亂碼寫進 SCM。
- **產品版號唯一真相來源 = repo 根目錄 `Directory.Build.props` 的 `<Version>`**（格式 `YY.A.B`，規則見 CLAUDE.md §版本號規則）。MSBuild 自動套到所有 csproj（exe 檔案屬性、Web footer 讀 `AssemblyInformationalVersion`）；BuildRelease.ps1 讀同一檔寫進 Release 包名 `SCADA_Release_<yyyyMMdd_HHmm>_v<版號>` 與四個服務的描述。改一處四處同步。包名保留 `SCADA_Release_<日期>` 前綴，QuickDeployAll.bat 以名稱倒序取最新不受影響。
- **描述每次安裝都刷新**（`sc description` 不受「服務已存在」限制），所以升級後 services.msc 看到的版號就是現場實際版本。

**舊名遷移（v26.1.0 前的現場）**：Windows 服務無法改名，Install.bat 在停服務段後對 `ScadaEngineService` / `ScadaWebService` / `ScadaEngineLicense` 逐一 `sc query` → 存在就 `net stop` + `sc delete`，再以新名 `sc create`；InstallModbusServer.bat 對 `ScadaModbusGatewayService` 同理。不做遷移的後果：新舊服務指向同一個 exe 且都自動啟動，Web 搶 5038、Engine 雙重採集。
- 執行安裝時 **services.msc 要關掉**，否則 `sc delete` 只標記待刪，舊名要重開機才消失（新名照常建起、照常啟動，不影響功能）。
- Engine 的 `LicenseService.cs` 自救邏輯（License 服務不存在就 `sc create`）同步改用 `JoularisLicense`，否則會自己把舊名建回來。Named Pipe 名稱 `ScadaEngineLicense` 是內部協定，不隨改名動。
- 防火牆規則同時改名（`JOULARIS Web` / `JOULARIS Web HTTPS` / `JOULARIS Modbus Gateway TCP|Web`），安裝時先刪舊名規則再加新規則。
- 事件檢視器來源名稱一併改（`JOULARIS Engine` / `JOULARIS Modbus Gateway`），舊紀錄留在舊來源下不搬。
- 各專案 `Scripts\Deploy*.ps1`（開發 / 手動部署用）只改名不做遷移；生產機一律走 Install.bat。

## Python 基礎包版號機制

- 建包時 `BuildRelease.ps1` 把 `ScadaEngine.Engine\PythonRuntime` 複製到 **package 根目錄 `PythonRuntime\`**，並寫入 `VERSION` 檔。
- `VERSION` 內容 = `python 版本_檔案數_總位元組`。改 Python 版本或 pip 套件 → 三者任一變 → 版號變。
- `Install.bat` 安裝 Engine 後，比對 package 的 `PythonRuntime\VERSION` 與目標機 `C:\JOULARIS\Engine\App\PythonRuntime\VERSION`：
  - 目標缺、或版號不同 → 重鋪（先刪再 xcopy）。
  - 版號相同 → **跳過那 62MB copy**。
- Engine 執行期讀 `C:\JOULARIS\Engine\App\PythonRuntime\python.exe`（`Worker.ResolvePythonExe`）。Engine 的 App xcopy **不含也不清除** PythonRuntime，故既有 Python 在 App 覆蓋時存活，由版號機制決定是否刷新。

## 常態遠端更新流程（無 SSH 也適用）

只改了 C# 碼、Python 沒動時，產 app-only 更新包：

```powershell
# 開發機
.\BuildRelease.ps1 -NoPython
```

- 產出的包**不含 `PythonRuntime\`**，體積更小，適合 USB／雲端硬碟／email 任何通道搬到現場。
- 現場跑 `Install.bat`：
  - runtime 偵測照跑（目標機已有 runtime → 通過）。
  - Python 段落偵測到「包內無 bundle」→ 保留目標機現有 Python，只在完全沒有 Python 時警告。
  - 現場設定（Modbus / Setting / DBPoint / MqttSetting）照舊備份→還原，不受影響。

> 完整包（含 Python）用於首裝、或 Python／pip 套件有變更時：直接 `.\BuildRelease.ps1`（不加 `-NoPython`）。

## 在 macOS 上建包（26.17 起）

`BuildRelease.ps1` 已跨平台：在 Mac 上也能產出與 Windows 建機完全相同結構的 Release 包（Windows exe 由 `dotnet publish --runtime win-x64` 交叉產出，net48 的 LicenseBridge 靠 SDK 自帶的參考組件編譯）。`.bat` 檔 macOS 無法執行，改用同目錄的 **`BuildRelease.command`**（Finder 雙擊或終端機執行，參數原樣轉給 ps1）。

### 一次性安裝（不需要 Homebrew、不需要 sudo）

```bash
# .NET 8 SDK → ~/.dotnet
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 8.0
# PowerShell 7 以 dotnet 全域工具安裝 → ~/.dotnet/tools/pwsh
~/.dotnet/dotnet tool install --global PowerShell
# 讓終端機找得到（寫進 ~/.zshrc）
echo 'export PATH="$HOME/.dotnet:$HOME/.dotnet/tools:$PATH"' >> ~/.zshrc
echo 'export DOTNET_ROOT="$HOME/.dotnet"' >> ~/.zshrc
```

### 建包

```bash
cd ~/Repo/JOULARIS
./BuildRelease.command -NoPython     # app-only 更新包（常態）
./BuildRelease.command               # 完整包，需先備妥 PythonRuntime（見下）
```

產物在 `Release/SCADA_Release_<日期>_v<版號>/`，整個資料夾搬到 Windows 目標機後以系統管理員執行 `Install.bat` 即可，流程與 Windows 建機產出完全相同。

### 跨平台細節（維護者須知）

- **路徑分隔符**：ps1 內所有路徑拼接改用 `/`（Windows PowerShell 一樣接受）；macOS 上 `\` 是合法檔名字元，沿用舊寫法會產出名為 `...\Engine\App` 的單一目錄。只有 Install.bat / InstallModbusServer.bat 兩段 here-string 內容維持 Windows 寫法（那是給 cmd.exe 跑的）。
- **bat 換行**：兩支 bat 產物寫檔前強制轉 CRLF（`-replace "\`r?\`n", "\`r\`n"`）。Mac 上 checkout 是 LF，cmd.exe 遇到 LF-only 的 bat 在 `goto` / 多行括號區塊會出錯。
- **Python 基礎包**：`SetupPythonRuntime.ps1` 要執行 Windows `python.exe` 裝 pip，Mac 做不到。完整包要在 Mac 產，須先把任一 Windows 機的 `C:\JOULARIS\Engine\App\PythonRuntime\` 整包複製到 repo 的 `ScadaEngine.Engine/PythonRuntime/`（已被 .gitignore 排除）；沒有就只能 `-NoPython`，腳本會明確報錯中止。VERSION 版號的 Python 版本在 Mac 讀不到 PE 資源，改由 `python3XY.dll` 檔名推得，與 Windows 產的字串一致。
- **目標機前置需求不變**：ASP.NET Core Runtime 8.0.x (x64) + .NET Framework 4.8，Install.bat 照常偵測。

## 不採用的做法（記錄取捨）

- **Trimming（`PublishTrimmed`）**：Dapper／OPC UA／Roslyn／JSON 反射重，trim 掉的型別會在生產環境才炸，開發期測不出，風險 >> 收益，且已 framework-dependent，不需要。
- **ReadyToRun**：讓包變大，與省空間相反。
- **Single-file**：總大小幾乎不變，還跟 HASP／Python 原生 dll 打架。
- **保留 self-contained 後備建包模式**：不保留（一律要求目標機裝 runtime）。
- **rsync/robocopy 差異同步、dev 端 hash 差異包**：需可連線通道或額外 manifest 基建，暫不做；日後若要把每次更新壓到 ~6–15MB 再另評估。
